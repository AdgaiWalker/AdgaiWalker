## 1. 产品摘要

AdgaiWalker 已有“线索 Clue → 题苗 Seed → 执行 Execution → 交付与检验”经营内核，以及 `content/log` 文章真相源、Git 发布管线和 `iwalk.pro` 公开站。

本产品在现有内核上增加一个本地 AI 自媒体工作站，用一条可追溯流程完成：

```text
发现真实问题
→ 调查和分析
→ 管理与主选选题
→ 作者写核心观点和初稿
→ AI 编辑、检查、制作和排版
→ 作者最终审批
→ 网站发布和公众号辅助填写
→ 数据、反馈和新问题回收
```

产品不要求用户一开始就准备好所有 Skill、MCP 和外部工具。无 AI 或工具失败时，人可以接管任意阶段，上传结果后继续后续流程。

## 2. 背景与问题

### 2.1 当前问题

1. 问题、灵感、评论和用户反馈分散，没有稳定地进入选题库。
2. 选题判断依赖临时感觉，缺少真实性、证据、用户价值和商业价值的统一评估。
3. 初稿之后的编辑、检查、封面、排版和发布有大量重复劳动。
4. 任务排期容易变成硬性日程，不适合单人自媒体的弹性工作节奏。
5. 一个工具或平台失败时，容易迫使整条流程重来。
6. 已发布内容与用户的真实完成结果、咨询需求和后续选题没有自然连接。
7. 外部 Skill、MCP 和 GitHub 项目缺少统一的安装、权限、版本和失败恢复机制。

### 2.2 机会

将自媒体从“持续发内容”改造为“发现问题—解释问题—帮助完成—验证价值—沉淀资产”的可追溯经营系统。

## 3. 产品目标

### 3.1 P0 目标

1. 支持一篇作品从问题调查进入选题，从人工初稿进入 AI 加工、审批、发布和复盘。
2. 作者在正常情况下只需做四类核心动作：选题、写初稿、审核成品、确认公众号公开。
3. AI 或工具失败时，已成功的阶段不丢失，人可以接管当前阶段。
4. 新 Skill、MCP 或外部工具可在不改业务流程代码的前提下注册、启用、停用和替换。
5. 系统不强制为行动设置截止时间，计划日期可为空。

### 3.2 验证指标

| 指标 | P0 验收线 |
|---|---|
| 真实作品数 | 连续完成 3 篇 |
| 单篇人工内容审批 | 正常流程 1 次 |
| 网站发布 | 3 篇均可从正式 URL 访问 |
| 公众号准备 | 3 篇均形成完整草稿包 |
| AI 加工返工 | 至少 2 篇无需人工重做加工阶段 |
| 失败恢复 | 任意模拟失败可从最近成功 Artifact 继续 |
| 工具替换 | 停用一个工具后可换工具或人工接管 |
| 追溯性 | 原稿、阶段结果、审批版和发布版哈希可查 |

## 4. 非目标

P0 不包含：

- 多人协作、组织和复杂角色权限；
- 公网管理后台和远程上传；
- 完整客户、订单、报价、合同和财务系统；
- 小红书、B 站、抖音和 X 的全自动发布；
- 全平台数据自动回收；
- 通用插件市场、付费、评论和自动推荐；
- 完整容器沙箱、远程 Tool Runner 和分布式任务队列；
- AI 自动主选、自动改变作者核心立场或未经审核直接发布；
- 伪造认证、破解验证码、规避风控或绕过平台权限；
- 删除线上内容。

## 5. 用户与核心任务

### 5.1 核心用户

用户是每周可投入 10–20 小时的单人自媒体经营者，会自己写观点和初稿，希望将重复的调查整理、编辑、检查、制作、排版、发布和复盘交给 AI。

### 5.2 用户要完成的任务

1. 遇到一个真实问题时，快速记录并让 AI 帮忙调查。
2. 在候选题中看到证据、价值、成本和差异性，然后自己决定做哪个。
3. 从内容任务书开始写初稿，不让 AI 代写人格和立场。
4. 上传初稿和素材后，让 AI 完成可自动化的加工。
5. 在一个审批页看完修改、风险、封面和平台预览。
6. 在不被硬日程绑架的前提下，安排什么时候写、录、制作和复盘。
7. 工具失败时，重试、换工具、人工接管或导出作品包。
8. 发布后记录真实结果，把新问题回写到下一轮调查和选题。

## 6. 产品原则

1. **一套业务真相。** 问题在 Clue，选题在 Seed，执行在 Execution，作品加工在 Submission，发布在 Publication，行动在 Action。
2. **人保留主体性。** AI 可以研究、评分和建议，选题主选、核心观点、初稿和最终审批由人完成。
3. **安全高于质量，质量高于效率。** 安全检查未通过时不进入发布。
4. **原稿永不覆盖。** 每个阶段产生新 Artifact。
5. **业务阶段稳定，工具可替换。** 配方依赖 capability，不写死某个工具名。
6. **排期可选。** 无日期 Action 是正常状态，过了计划日期不自动标记失败。
7. **可逆和可恢复。** 勾选可撤销，审批可退回，工具可停用，作品可从历史 Artifact 恢复。
8. **即时且连续的反馈。** 操作从按下开始给反馈，长任务持续显示阶段、耗时和可终止状态。
9. **先常用路径，后高级选项。** 默认页面只展示当前最需要的决策和动作。
10. **一人可养。** 不为尚未验证的未来协作需求增加复杂度。

## 7. 人与 AI 责任边界

| 阶段 | AI 责任 | 人的责任 |
|---|---|---|
| 问题调查 | 搜集、去重、聚类、标注证据和不确定性 | 判断是否认可这是真问题 |
| 选题 | 评分、排序、建议形式和平台 | 选哪个题、现在做不做 |
| 内容任务书 | 整理用户、场景、证据、结构和行动目标 | 确定核心立场 |
| 初稿 | 提供资料和必要追问 | 自己完成观点和第一版表达 |
| 内容加工 | 结构、润色、查错、补证据、排版和封面 | 决定实质观点变更 |
| 审批 | 展示差异、风险和预览 | 批准、退回、恢复或取消 |
| 发布 | 网站推送、公众号填写和结果记录 | 公众号最终公开确认 |
| 复盘 | 聚合数据、反馈和再利用建议 | 决定定位、产品和长期方向 |

## 9. 端到端业务流程

### 9.1 从问题开始

```text
输入一个问题、评论、私信摘要或项目困难
→ 创建/关联 Clue
→ AI 调查与证据分类
→ 去重与聚类
→ 创建/更新 Seed
→ AI 评分与排序
→ 人工主选
→ 创建 Execution、内容任务书和无日期 Action
```

### 9.2 从初稿开始

```text
选择已有 Execution 或新建人工主选项目
→ 上传文字、图片、视频、音频和链接
→ 创建 Submission
→ 保存只读原稿
→ 解析混合素材
→ 选择 Recipe 和工具
→ 逐阶段生成 Artifact
→ 事实、隐私、夸大和核心观点检查
→ 冻结正文
→ 生成双封面、网站稿和公众号稿
→ 统一审批
```

### 9.3 发布与回流

```text
批准 Artifact
→ 网站 Publication 和公众号 Publication 独立执行
→ 记录 URL、时间、快照和错误
→ 录入首批数据和用户反馈
→ AI 生成复盘和再利用建议
→ 回写新 Clue、Seed 和 Action
```

| ANA-05 | 生成新 Seed、拆条建议和商业需求提示 | P1 | 需要人确认后才进入候选池 |
| ANA-06 | 全平台自动数据回收 | P2 | 平台账号权限可查、可撤销、可停用 |

### 10.11 工具中心

| ID | 需求 | 优先级 | 验收标准 |
|---|---|---|---|
| TOOL-01 | 列出 Skill、MCP、Adapter 和 Recipe，显示来源、版本、许可证、权限和状态 | P0 | 每个工具有独立详情和审计记录 |
| TOOL-02 | 从本地路径、固定 Git 版本或 MCP 配置发现工具 | P0 | 发现阶段只读元数据，不执行未审查代码 |

|---|---|---|---|
| SYS-01 | 保存每个成功 Stage 的 Artifact、哈希、时间和工具版本 | P0 | 重启应用后可从最近成功 Stage 继续 |
| SYS-02 | 单个 Stage 最多自动重试两次 | P0 | 超过两次进入 FAILED 或 NEEDS_INPUT，不无限循环 |
| SYS-03 | 运行中任务可终止，已完成 Artifact 不丢失 | P0 | 终止后状态和日志一致 |
| SYS-04 | 日志脱敏，不保存密码、Cookie 全文和私密原稿全文 | P0 | 自动化测试包含敏感信息样例 |
| SYS-05 | 导出完整作品包 | P0 | 导出包包含调查、任务书、原稿、阶段结果、封面、平台稿和发布记录 |

## 11. 状态模型

### 11.1 Clue 与 Seed

```text
Clue: CAPTURED → RESEARCHING → VALIDATED | NEEDS_EVIDENCE | REJECTED
Seed: INBOX → EVALUATED → READY → SELECTED | ARCHIVED
```

- `VALIDATED` 表示足以进入选题池，不表示所有 AI 推断已成为事实。
- `SELECTED` 只由用户动作产生。

### 11.2 Submission

```text
UPLOADED
→ EXTRACTING
→ PLANNING
→ PROCESSING
→ QUALITY_CHECKING
→ REVIEW_READY
→ APPROVED
→ PUBLISHING
→ PARTIALLY_PUBLISHED | COMPLETED
```

辅助状态：`NEEDS_INPUT`、`CHANGES_REQUESTED`、`FAILED`、`CANCELLED`。

### 11.3 Action

```text
OPEN → DONE
DONE → OPEN
```

### 11.4 ToolInstallation

```text
DISCOVERED → INSPECTED → DISABLED → ENABLED → UNHEALTHY | QUARANTINED
```

### 11.5 Publication

```text
PENDING → PUBLISHING → PUBLISHED | FAILED | WAITING_USER
```

## 13. 体验与交互规范

本节将 Apple Design 的 Purpose、Agency、Responsibility、Familiarity、Flexibility、Simplicity、Craft 和 Delight 转换为本产品的可验收需求。目标情绪是：**安静、可控、有进展感**。

### 13.1 反馈

- 按钮在 pointer-down 立即改变材质或缩放，提交在 pointer-up 完成。
- 长任务不只显示转圈，而是显示当前 Stage、已用时间、最近产出和可终止操作。
- 反馈分为状态、完成、警告和错误，不只使用颜色区分。
- 表单就地验证，错误靠近对应字段，不等到提交后统一报错。

### 13.2 操作权与可逆性

- AI 推荐不伪装成系统决定；“AI 建议”与“我已选定”在视觉和文案上分开。
- 勾选 Action、改变计划日期、退回审批和切换工具都提供撤销。
- 确认对话只用于不可逆的删除和公开发布。
- 任何运行中动效不锁死输入，面板在动画中仍可被关闭或反向操作。

### 13.3 直接操作

- 拖动 Action 时卡片保持人抓取时的偏移，不瞬间跳到指针中心。
- 拖动过程使用 Pointer Events 和 pointer capture，卡片 1:1 跟随指针。
- 移动阈值约 10px 后才进入拖动，避免点击被误判。
- 越过日历边界时使用渐进阻力，不使用硬停。
- 拖动释放时动画继承释放速度，并落到最近有效日期。
- 键盘用户可通过快捷菜单完成相同的移动和排期操作。

### 13.4 动效

- 普通过渡采用临界阻尼、无过冲的弹簧，目标响应 0.3–0.4 秒。
- 只有由甩动、拖动释放或其他动量操作触发时才允许轻微回弹。
- 面板从触发它的按钮方向出现，关闭时沿同一路径返回。
- 可操作对象只使用 transform 和 opacity 执行每帧动效。
- 先读取屏幕当前呈现值，再反转动画，不从逻辑终点突跳。

### 13.5 材质与层级

- 侧边栏、顶部工具栏和非阻断信息面板可使用适度透明材质和 `backdrop-filter`。
- 任务审批等阻断面板使用遮罩层；工具详情等并行面板不用遮罩，保留工作连续性。
- 大表面的模糊、阴影和视觉重量高于小表面，不叠加多层轻透明表面。
- 滚动内容与悬浮工具栏之间使用渐变/模糊边缘，不依赖粗重实线分割。

### 13.6 字体与密度

- 优先使用系统字体栈，中文依赖操作系统的默认中文字体。
- 大标题紧行高和负字距，正文使用舒适行高，小字提高字距和对比度。
- 字号、间距和控件高度使用 rem/em 或可缩放 token，不在用户增大字号时截断内容。

### 13.7 无障碍与降级

- `prefers-reduced-motion: reduce` 下将滑动、弹簧和视差替换为短淡入/淡出或静态反馈。
- `prefers-reduced-transparency: reduce` 下提高背景不透明度并取消模糊。
- `prefers-contrast: more` 下使用近实色背景和明确边框。
- 所有拖动、勾选、主选、审批和工具权限操作支持键盘和可读标签。
- 点击目标提供足够大的操作区域，不仅依赖小图标。

## 14. 技术栈

### 14.1 总体决策

为最快开发，P0 不更换现有框架，不迁移 Next.js，不拆微服务，不引入 Redis 和消息队列。

| 层 | 技术 | 决策 |
|---|---|---|
| 包管理 | pnpm 9.15 | 继续使用现有 workspace |
| 运行时 | Node.js 20+ | 与现有项目和 Codex CLI 兼容 |
| Admin | React 19 + Vite 6 + React Router 7 | 扩展现有 `apps/admin` |
| 公开站 | React 19 + Vite 6 + Tailwind CSS 4 | 继续现有 `apps/web` |
| API | NestJS 11 + Express adapter | 扩展现有 `apps/api` |
| 数据库 | Prisma 6 + SQLite | P0 本机运行，同步保持 PostgreSQL schema 对齐 |
| 共享契约 | TypeScript + `@walker/shared` | 放置类型、状态、规则和路由 SSOT |
| AI 主执行器 | 本机 Codex CLI | NestJS 以子进程非交互调用 |
| AI 输出 | JSONL 事件 + JSON Schema 最终结果 | 过程可观测，结果可验证 |
| 本地文件 | `var/works` + `var/tools` | Artifact 和工具运行时不进 Git |
| 内容发布 | Markdown + 现有 `content:gen` / `content:publish` | 不建第二套公开内容存储 |
| 公开站托管 | GitHub `main` → Vercel | 继续只部署静态 web |
| 测试 | Vitest + Testing Library + 现有 acceptance scripts | 不另建第二套测试框架 |

### 14.2 Admin 前端技术决策

- 继续使用现有 `admin-api` 门面和页/块分层。
- P0 不引入全局状态巨石；服务端数据由页级 hooks 和门面管理。
- 现有 `styles.css` 扩展为 token + 基础组件样式，P0 不为了样式重写 Admin 的 CSS 框架。
- 为日历/行动拖动引入 `@dnd-kit/core` 和 `@dnd-kit/sortable`，使用其键盘感知和无障碍能力。
- 为可中断弹簧、面板和拖动释放引入 `motion`。非手势过渡优先使用简单 CSS。
- 所有业务路径写入 `ADMIN_ROUTES`，组件不硬编码路径。

### 14.3 NestJS 模块

P0 在现有 API 中增加边界清晰的模块：

```text
research       调查 Artifact 与证据标注
topics         Seed 评分、聚类、主选前准备
actions        Action 创建、排期、勾选和日志
submissions    Submission 、上传和作品目录
workflows      Recipe、Stage 状态机和恢复
agent-runner   Codex CLI 调用、JSONL 解析和终止
tools          ToolInstallation、manifest、capability 解析
artifacts      Artifact 读写、哈希和 schema 验证
reviews        冻结、差异、审批和恢复
publications   网站和公众号 Publication
retrospectives 数据、反馈、复盘和回流
brand          Brand Profile 和可公开素材引用
```

业务 Service 依赖 Port，文件、Prisma、Codex 和发布脚本通过 Adapter 实现。

### 14.4 AI 执行架构

```text
Admin 发起 Stage
→ NestJS 校验业务状态和权限
→ AgentRun 持久化
→ Node.js child_process 启动 codex exec
→ 限定工作目录、输入 Artifact 和 profile
→ 解析 JSONL 事件并回写进度
→ 用 JSON Schema 验证最终结果
→ 原子保存新 Artifact
→ 推进 Stage 或进入 NEEDS_INPUT/FAILED
```

Codex 执行约束：

- 使用子进程输入，不把私密原稿写入命令行参数。
- 使用 `workspace-write` 或更严格的工作目录权限。
- 禁止使用跳过审批和沙箱的危险参数。
- 每个 Stage 使用独立运行目录和输出 schema。
- 超时可终止，标准输出、标准错误和 JSONL 日志脱敏。
- P0 不在 NestJS 中重新开发通用 Agent 框架。

### 14.5 Tool Runner 与可加载能力

工具类型：

| 类型 | 作用 |
|---|---|
| Skill | 教 AI 怎样做，本身不新增系统权限 |
| MCP | 通过标准协议提供 Resources、Tools 和 Prompts |
| Adapter | 包装普通 CLI、API、GitHub 项目或浏览器操作 |
| Recipe | 把业务阶段、capability、参数和人工门组成流程 |

统一 manifest 至少声明：id、kind、source、pinnedVersion、license、capabilities、inputSchema、outputSchema、runtime、permissions、credentialRefs、healthCheck、timeout、retry、dataHandling 和 rollback。

P0 工具安装与运行使用本地目录和独立子进程。这是轻量隔离，不宣称为完整安全沙箱。

### 14.6 P0 外部 Skill

| 能力 | 来源 | 用法 |
|---|---|---|
| 封面策划 | `pyang5166/gbro-cover-design` | 输出中文生图提示词，由独立 Image Generator Adapter 生图 |
| 公众号基础排版 | `isjiamu/gzh-design-skill` | 将冻结 Markdown 转为公众号 HTML |
| 公众号移动端优化 | `cyberxiaowan/xiaowan-wechat-layout-skill` | 优化层级、留白、重点句、断行和 390px 预览 |

Git 来源在首次安装时固定到具体提交。MIT 和 AGPL 依赖的许可证信息在工具中心展示；未来云化或对外提供网络服务时重新审查 AGPL 义务。

### 14.7 凭据与配置

- Codex 使用本机已有认证。
- 其他工具的密钥不写入 SQLite、manifest、Artifact 或 Git。
- P0 的 credential reference 只指向本地环境变量或操作系统/工具已有凭据。
- 宿主在当次运行注入获批凭据，不向工具暴露完整凭据集。

## 15. 业务兜底

兜底顺序固定为：

```text
当前 Stage 自动重试
→ 更换已安装的同 capability 工具
→ 人工接管当前 Stage
→ 导出完整作品包
```

### 15.1 兜底操作

任何失败页统一提供：

- 查看失败原因；
- 重新执行；
- 更换工具；
- 人工完成并上传 Artifact；
- 恢复上一个成功版本；
- 跳过非必要 Stage；
- 导出作品包；
- 取消当前作品。

### 15.2 分阶段兜底

| 阶段 | 正常方式 | 兜底方式 |
|---|---|---|
| 问题调查 | AI 搜索和分析 | 用户粘贴资料，系统保存调查清单和证据缺口 |
| 选题评分 | AI 自动评分 | 人工填写或直接主选 |
| 内容任务书 | AI 生成 | 使用固定任务书表单 |
| 初稿 | 作者自己写 | 该阶段本身不依赖 AI |
| 内容编辑 | Codex 加工 | 使用原稿或上传人工修改稿 |
| 事实检查 | AI 核验 | 标记待人工核实，未核实内容不伪装通过 |
| 封面策划 | GBRO | 使用 Brand Profile 中的固定封面模板 |
| 封面生成 | Image Generator Adapter | 上传人工制作封面 |
| 公众号排版 | 排版 Skill | 使用基础安全 HTML 或上传人工 HTML |
| 网站发布 | 自动构建与推送 | 导出发布包并运行现有 pnpm 发布流程 |
| 公众号填写 | 浏览器辅助 | 下载 HTML 和素材后人工复制上传 |
| 数据回收 | 已授权工具读取 | 手工录入关键数据 |
| 复盘 | AI 分析 | 使用固定复盘问题清单 |

### 15.3 业务连续性底线

1. 原稿永久保留。
2. 已成功 Stage 永久保留。
3. 只重做失败 Stage。
4. 人可以接管任意制作 Stage。
5. 人工完成后可重新交给 AI。
6. 网站和公众号独立成败。
7. 没有 AI 时仍可完成和发布作品。
8. 任何时候可导出完整作品资产。

## 16. 安全与权限

### 16.1 权限原则

- 安装时确认工具可能需要的最大权限。
- 运行时只授予当前 Stage 实际需要的文件、域名和 credential reference。
- 新版本增加权限时必须重新确认。
- Skill、MCP 和 Adapter 不能写入正式内容目录，只能产生 Artifact。
- 发布器只消费已批准 Artifact。

### 16.2 发布前硬检查

- 原稿存在且哈希未变；
- 核心观点无未说明改变；
- AI 新增事实有来源或明确标记；
- 无私密资料泄露；
- Markdown 可构建；
- 网站素材无本地临时路径；
- 公众号 HTML 无脚本、乱码和失效图片；
- 390px 预览无严重错位；
- 双封面中文标题逐字正确；
- 发布 Artifact 哈希等于批准哈希。

## 17. 可观测性

### 17.1 需记录的运行事件

- 对象创建和状态变更；
- Recipe 与 capability 解析结果；
- 工具 id、版本和权限快照；
- Stage 开始、结束、超时、终止和重试；
- Artifact 输入/输出哈希；
- 人工主选、审批、退回、恢复和手工接管；
- Publication 推送、验证、失败和结果；
- 工具安装、权限确认、启用、禁用、不健康和隔离。

### 17.2 用户可见的错误

错误必须回答：

1. 在哪个阶段失败；
2. 已保留到哪个成功结果；
3. 用户现在可以重试、换工具、人工完成还是需要补充信息；
4. 是否影响另一发布平台；
5. 错误详情是否含敏感信息并已脱敏。

## 18. 测试与验收

### 18.1 单元与规则测试

- AI 不能将 Seed 自动推进到 SELECTED。
- AI 创建 Action 默认 plannedDate 为空。
- Action 勾选和恢复正确写入/清空 completedAt。
- 未批准 Submission 不能进入发布。
- 工具不能读取未映射文件或未授权凭据。
- 工具输出不符合 schema 时不推进 Stage。
- 网站和公众号 Publication 状态互不覆盖。

### 18.2 集成测试

- SQLite 中的对象与本地 Artifact 目录一致。
- Codex JSONL 事件正确转换为 AgentRun 进度。
- 超时和人工终止不污染上一个 Artifact。
- 封面文字错误时只重做相应封面。
- 排版 Stage 不修改冻结正文。
- 发布器检测并拒绝无关 Git 改动。
- 人工 Artifact 接管后可继续后续 Stage。

### 18.3 交互与无障碍测试

- 主导航、表单、拖动、勾选、审批和错误处理可仅用键盘完成。
- 拖动与释放动效可在任意时刻中断。
- reduced motion 下不使用大幅滑动、回弹和视差。
- reduced transparency 和 increased contrast 下导航、面板和文字可读。
- 放大文字后不遮挡主操作和状态。

### 18.4 真实业务验收

每个实施切片先使用一条真实数据验收，最终连续运行 3 篇作品，记录：

- 从问题输入到人工主选的时间；
- 作者实际操作时间；
- AI 自动执行时间；
- 人工被提前打断的次数；
- 审批退回次数；
- 工具解析、超时、失败和回滚次数；
- 人工接管的 Stage 和原因；
- 网站和公众号最终结果；
- 首批数据、用户反馈、真实完成数和新 Clue 数。

## 19. 实施切片

### Slice 1：经营入口

范围：Clue 调查 Artifact、Seed 选题库、内容任务书、Action 自由排期和视频日志。

验收：一个真实问题经调查和人工主选后，产生 Execution、任务书和无日期初稿 Action。

### Slice 2：可加载执行层

范围：manifest、ToolInstallation、capability 解析、Codex Agent Runner、轻量 Tool Runner 和手工 Artifact 接管。

验收：一个样例 Skill 可安装、检查、启用、执行、禁用；禁用后可人工上传相同 schema 的 Artifact。

### Slice 3：作品制作

范围：Submission、混合资料包、基础 Recipe、初稿后加工、双封面、公众号排版和最终审批。

验收：一篇真实初稿形成网站 Markdown、公众号 HTML、双封面和可批准 Artifact。

### Slice 4：发布与复盘

范围：Website Publisher、WeChat Assisted Publisher、Publication、数据/反馈录入、复盘和新 Clue 回写。

验收：批准作品发布到 `iwalk.pro`，形成公众号完整草稿包，录入首批结果并生成复盘。

## 20. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| Codex CLI 版本变化 | 输出事件或参数变化 | 固定已验证版本，封装 AgentRunnerPort，用契约测试防止直接渗透 |
| 本机进程中断 | 长任务停止 | AgentRun 持久化，Stage 原子保存，重启后从最近成功点继续 |
| 外部 GitHub 项目不可信 | 本地文件、凭据或网络风险 | 固定版本、manifest、权限确认、独立目录、最小映射和可隔离状态 |
| AI 改变作者观点 | 个人品牌失真 | 核心观点单独保存、修改摘要、观点风险和最终人工审批 |
| 公众号页面变更 | 辅助填写失败 | Publication 独立重试，导出 HTML/素材包，人工复制上传 |
| Git 工作树含用户改动 | 误提交其他文件 | 推送前检查预期文件集，发现无关改动就停止 |
| SQLite 和 PostgreSQL schema 漂移 | 未来切换困难 | 每次模型改动同步更新两份 schema 并做对齐测试 |
| Apple 风格变成装饰性动效 | 界面慢、晕动和分心 | 动效只服务于反馈、空间关系和直接操作，完整支持 reduced motion |

## 21. 已确定决策

1. P0 是 Windows 本机工作站，不先做云端 Admin。
2. 使用现有 pnpm monorepo、React/Vite、NestJS、Prisma/SQLite 和静态 Vercel 网站。
3. P0 的 AI 主执行器是本机 Codex CLI，NestJS 不重建通用 Agent 框架。
4. P0 不同时开发第二套 AI 引擎，人工 Artifact 接管是最终业务兜底。
5. 兜底顺序是自动重试、更换已有工具、人工接管、完整导出。
6. 网站批准后可自动发布；公众号辅助填写后由用户最终确认公开。
7. 计划日期可空，系统不创建默认硬截止时间。
8. 选题使用现有 Seed，不建并行的第二套选题真相。
9. 公开文章继续以 `content/log` 为真相源。
10. 新工具安装不等于信任，必须经过来源固定、权限确认和健康检查。

## 22. P0 最终验收场景

验收人在 Windows 本机完成以下全流程：

1. 记录一个真实问题。
2. 生成一份区分事实、他人观点和 AI 推断的调查摘要。
3. 将问题转为 Seed，查看七维评分和理由。
4. 人工主选 Seed，生成 Execution、内容任务书和无日期 Action。
5. 作者完成初稿，上传混合素材包并创建 Submission。
6. Codex 根据 Recipe 完成结构编辑、语气保护、事实、隐私和夸大检查。
7. 系统冻结正文，生成双封面、网站 Markdown 和公众号 HTML。
8. 作者在一个审批页检查原稿差异、风险、封面和双平台预览。
9. 批准后发布到 `iwalk.pro`，并生成可人工最终确认的公众号草稿包。
10. 录入首批数据和用户反馈，生成复盘并回写一个新 Clue。
11. 人为让一个制作 Stage 失败，验证重试、更换工具或人工 Artifact 接管。
12. 导出完整作品包，确认在 AdgaiWalker 和 Codex 不可用时仍能读取并继续人工工作。
