# PRD：站主内容与 Agent 运营后台

版本：v0.2 · 2026-09-22 · 访谈草稿，补充访客 AI 交互数据与日志，待站主审阅。

配套：[开源选型调研](RESEARCH-AGENT-OPS-OPEN-SOURCE.md) · [技术方案 v0.2](TECH-DESIGN-AGENT-OPERATIONS.md)。技术方案为实施提案，不表示产品能力已实现；本 PRD 的已确认需求与待澄清项保持有效。

本文描述新后台的目标行为；F01–F18只读框架已本地验收，见[验收报告](ADMIN-FRAMEWORK-ACCEPTANCE.md)，其余业务尚未实施，生产未上线本次重构。旧后台页面已退役，旧 PRD 仅提供可复用资产线索。本文中的“已确认”来自本次站主访谈；具体默认值、首期切分与交互均为产品建议。实施排期仍统一维护在根 `PLAN.md`，本文不建立第二份执行计划。

配套研究：[开源项目选型调研](RESEARCH-AGENT-OPS-OPEN-SOURCE.md)。复用方案尚待验证，不改变本文的产品权限与验收要求。

## 1. 产品结论与决策依据

**让站主用一个后台管理内容、把 Agent 配置到前台提供服务，并根据运行结果和更新提醒持续经营站点。**

站主以自媒体为主要方向，目前还没有稳定的运营体系与方法论。系统应支持简单的计划、实际产出和反馈积累，帮助方法自然形成；首期不强迫站主遵循固定的选题、创作或增长流水线。

### 1.1 已确认

| 事项 | 站主意图 |
|---|---|
| 建设节奏 | 先搭可用框架，不要求一次完成所有功能 |
| 经营对象 | 文章、项目、小店运营等内容 |
| 日常工作 | 看关键数据与当前情况，规划内容，查看结果并复盘 |
| 访客价值 | 增强留住访客的能力；首先提供内容问答或主动介绍 |
| Agent 使用 | 后台创建 Agent，放到指定前台位置；一个位置可以配置多个 Agent 供调度 |
| 后台服务 | 更新内容状态，提醒站主该更新的事情 |
| 交互数据与日志 | 收集访客与 AI 的交互数据，后台可回看、分析并排查问题；列入首期需求 |
| 决定权 | 根据具体事项分级授予，允许最终授予完整职责范围内的决定权 |
| 唯一明确的 AI 写入红线 | **前台不得让 AI 修改站主内容**；其余授权机制由产品设计提出 |
| 执行基础 | 使用现有 DeepSeek Harness SDK |

### 1.2 产品假设与待澄清项

- 首期仅站主一人使用管理端，不建立团队岗位、组织层级或多人审批。
- 首个完整前台服务位置建议为“文章详情页”。项目页与小店位置按相同机制扩展。
- “内容状态实时更新”暂解释为：后台事实变化可及时看到，前台反映最近成功发布版本；是否包含持续追踪外部项目或商品变化，待站主补充。
- 小店首期管理商品/服务介绍等内容及更新事项；支付、订单、库存、履约不是已确认需求。
- “留住人”是产品目标，不是已被证明的效果；没有足够数据前不承诺留存增长比例。

## 2. 用户、价值与首期边界

### 2.1 用户与服务对象

- **站主**：管理内容、配置 Agent、决定授权、检查结果、处理提醒。
- **访客**：在具体内容旁获得解释、问答与相关内容引导；不会获得后台操作权限。
- **Agent**：受托执行者，拥有版本化配置和明确权限，不是权限授予者。

### 2.2 首期必须形成的闭环

1. 站主找到一篇已有文章，为它创建或选择 Agent。
2. 指定可读内容、服务位置和介绍方式，预览后启用。
3. 访客在文章旁提问，得到依据已发布内容的回答或诚实的无法回答提示。
4. 站主回看访客对话与服务日志，查看问题反馈、运行结果与到期更新提醒。
5. 站主更新内容并发布；后台显示发布结果，后续回答使用成功发布的新版本。

验收重点是以上真实过程能完成，不以页面数量、Agent 数量或图表数量衡量完成度。

### 2.3 首期范围与扩展边界

| 能力 | 首期交付 | 后续扩展 |
|---|---|---|
| 运营概览 | 内容变化、到期事项、待处理结果、Agent 服务情况 | 有数据后接入流量、回访与转化分析 |
| 内容管理 | 文章完整编辑/预览/发布；项目使用现有内容模型管理 | 小店内容的专用字段与页面，依实际经营补齐 |
| 小店入口 | 纳入内容类型规划；未接通时明确显示“尚未接入”，不能伪造记录 | 商品、服务介绍管理；交易系统另定范围 |
| 内容计划 | 给具体内容安排下一次更新事项和日期；支持无日期待办 | 系列内容计划、跨平台排期 |
| Agent 管理 | 创建、编辑、测试、版本、启停、后台直接调用 | 多 Agent 协作规划、技能导入等扩展 |
| 前台部署 | 文章详情页服务位置；多个候选 Agent、默认 Agent 和显式切换 | 项目/资源/小店位置，自动路由与接力 |
| 权限 | 前台只读；后台只读、候选产出、单次审批；提醒可持续自动执行 | 针对内容修改/发布的持续全权委托 |
| 提醒与复盘 | 到期扫描、后台提醒箱、人工处理记录、按时间查看结果 | AI 识别更新机会与定期复盘建议 |
| 监督 | 运行状态、输入输出、可用事件、版本、授权依据、失败与停止 | 更细粒度步骤控制，须先验证 SDK 支持 |
| 交互数据与日志 | 对话逐轮回看、AI 组件交互事件、运行/操作日志、筛选搜索、导出、保留与删除 | 问题自动聚类、跨会话趋势与运营建议 |

首期不含多租户、任意网页代码注入、可视化工作流编排器、跨平台自动发帖或交易履约。它们不是当前闭环的前置条件。

## 3. 信息架构与核心对象

### 3.1 后台工作面

| 工作面 | 站主在这里完成什么 | 主要内容 |
|---|---|---|
| 概览（默认首页） | 看现在发生了什么、哪里需要介入 | 关键数据、近期结果、提醒、失败/待审事项 |
| 内容 | 管文章与项目，安排更新，查看上线事实 | 列表、详情、编辑、预览、发布、更新事项、关联 Agent |
| Agent | 创建与调试 Agent，部署服务，授予职责 | 配置、版本、服务位置、可读范围、授权、运行记录 |
| 运营记录 | 回看访客需求、服务过程和运营结果 | 访客对话、运行日志、操作日志、发布、提醒处理和复盘 |
| 设置（低频） | 配置运行所需基础条件 | 模型连接、用量上限、AI 总开关、日志保留、系统健康 |

计划随内容对象维护；概览聚合到期事项。复盘从真实结果进入，首期不另建复杂计划中心或强制报表流程。

### 3.2 对象及其关系

| 对象 | 定义与必要信息 |
|---|---|
| 内容 | 文章/项目等持久内容；稳定 ID、类型、标题、修订版本、发布版本、更新时间 |
| 更新事项 | 针对内容的下一步工作；目标、关联内容、到期日（可空）、处理状态 |
| Agent | 可复用的服务角色；名称、职责、指令、模型、允许工具、知识范围、配置版本、启用状态 |
| 服务位置 | 前台代码支持的使用位置及内容范围；例如文章详情问答区；不能由模型任意创造前台组件 |
| 部署绑定 | 服务位置与 Agent 版本的关联；默认 Agent、候选列表、触发方式、部署状态 |
| 授权 | 站主对指定 Agent/任务允许的动作、对象、期限、额度和触发来源 |
| 运行 | 一次实际执行；触发者、来源、内容版本、Agent 版本、授权依据、状态、产物与事件 |
| 访客会话与消息 | 匿名会话及有序问答；消息 ID、角色、正文、时间、引用、对应运行、交付状态 |
| 交互事件 | AI 组件内的介绍展现/关闭、打开入口、提问、反馈、引用点击、Agent 切换等事实；有唯一事件 ID |
| 操作日志 | 站主或获授权 Agent 对配置、授权与内容等对象的操作事实，关联实际执行结果 |
| 提醒 | 需要站主注意的具体事项；原因、对象、来源、到期时间、处理结果 |

Agent 可以复用到多个位置，但每个位置都有独立的可读范围和只读权限。同一个 Agent 在后台获得写权限，不会把该权限带入前台会话。

内容原文、发布状态和运行记录分别沿用既有真相源；不为每个页面另存一份内容或状态。正文修订状态、项目业务进展与 Agent 运行状态是不同概念，不能合并成一个“状态”。

## 4. 产品行为

### 4.1 概览：先呈现事实

- 默认查看近 7 天，可切换近 30 天；显示时区、统计范围和最新更新时间。
- 第一屏回答：最近更新了什么、哪些事情到期、哪些执行需要介入、访客 Agent 服务是否正常。
- 每项统计能进入相关内容、事项或运行明细；没有来源的数据不画成已采集指标。
- 未接入显示“未接入”，无样本显示“暂无数据”，读取失败显示错误与重试；都不能用数值 0 代替。
- 首期不要求 AI 生成日报才能打开概览；事实统计独立于模型可用性。

| 首期指标 | 口径 |
|---|---|
| 成功发布次数 | 时间范围内线上验证成功的发布记录数；不把保存草稿计为发布 |
| 待更新事项 | 未完成且已到期的更新事项数；无日期事项单独列出 |
| 待介入事项 | 待审、失败、执行状态待核对的可操作事项，按稳定 ID 去重 |
| Agent 请求数 | 范围内服务端接受并记录的运行数；重试记录关联原运行 |
| AI 正常完成率 | AI 输出完成且校验通过的运行数 / 已进入终态的请求数；降级、失败、拒绝、取消另列，进行中不入分母 |
| 问答反馈 | “有帮助/没帮助”的有效反馈数与反馈率；模型自己判定的成功不等于访客满意 |
| 用量 | 已知 token 与其统计覆盖率；缺失不填 0，价格未配置不显示虚构金额 |

首期采集 AI 组件内的引用点击、继续提问等交互事实，口径见 §4.7；留人效果分析与跨会话回访指标后续补齐。首期不把停留时间或问答次数直接宣称为留存率。

### 4.2 内容、计划与发布

- 列表按类型、发布状态和更新事项筛选；详情同时呈现编辑版本与线上版本。
- 站主可以手动编辑、预览、保存、触发现有发布链路；AI 不可用不影响这些操作。
- 更新事项用一句话表达目标，允许暂时没有日期；完成时关联实际成果或填写说明，不能只因 Agent 返回文本就自动完成。
- Agent 生成的候选内容独立保存，展示与原文的差异；候选生成本身不覆盖原文。
- 保存成功不等于上线。发布失败保留原线上版本，显示失败阶段和可重试动作。
- 复盘支持记录“做了什么、看到了什么、下次尝试什么”，不要求套用固定运营方法论。

### 4.3 创建、调试与部署 Agent

1. 填写名称与职责，选择模型、可读内容和允许工具；新建默认处于草稿状态。
2. 在后台测试正常问答、内容未知和越权请求。首期提供这三类预置用例，保留测试结果；未通过权限校验不能部署。
3. 选择已有服务位置及生效范围，预览访客看到的界面。
4. 启用绑定，明确显示“启用中/已生效/失败”。只有服务端确认生效后才显示已部署。
5. 配置修改产生新版本；已部署版本不被草稿修改悄悄替换。站主可更新部署或回退到已知版本。

后台可随时选择已启用 Agent，在其授权范围内直接发起任务；每次调用有可回看的运行记录。禁用的 Agent 保留配置与历史记录，引用它的服务位置必须显示不可用并使用预设兜底。

### 4.4 前台问答、介绍与多 Agent 调度

- 首个位置建议为文章详情页的轻量入口：说明它能解释当前文章、回答问题和推荐相关内容。
- 默认只读当前已发布文章；站主可以扩展到指定公开内容集合，仍受 `aiUsePolicy` 限制。
- 主动介绍首期采用一个可关闭的小提示和示例问题，不自动展开遮挡正文，不自动发起持续对话。同一会话同一位置关闭后不再主动出现。
- 静态介绍文案可以在后台生成并确认，访客进入页面不必触发一次模型调用。
- 回答标明 AI 身份，引用可验证的内容出处。没有依据时明确说明，引导阅读相关内容或调整问题。
- 失败、配额耗尽或 AI 关闭时，提供规则提示和可读内容链接；不把规则回答标为 AI 成功。
- 一个位置可配置多个 Agent。首期调度是“默认 Agent + 访客显式切换”；当前回答者清楚可见。
- 切换 Agent 默认新建对话上下文；传递上下文必须限定在同一访客会话和共同获准内容范围内，不能串入后台任务或其他访客会话。
- 后续自动路由、协作、接力必须记录调度原因、参与者与成本，继承原始触发来源和权限上限，不得借调度提升权限。

前台可以记录访客问题、反馈和必要运行日志，这是服务过程数据；禁止把这些输入直接当成已授权的内容更新指令。

### 4.5 内容状态更新

- 后台自己的保存结果立即显示；发布和运行状态以服务端事实为准。首期建议在页面可见且联网时 5 秒内刷新已产生的状态变化。
- 超过 15 秒未获得新鲜状态时，显示最后同步时间和“同步中断/状态待核对”，不得继续假装实时。
- 前台正文沿用成功发布的静态内容。页面刷新和新会话读取最新已生效版本；首期不承诺浏览中的正文无刷新替换。
- Agent 记录本次使用的内容版本。新内容尚未进入问答索引时显示同步中，不能宣称更新完成；新页面版本与检索版本不一致时暂不做版本相关回答。
- 外部事实变化先形成带来源与核查时间的观察结果或提醒；不能因“实时”需求绕过内容写入权限。

### 4.6 更新提醒

- 首期支持站主设置“在某日提醒更新这篇内容”；重复规则为可选项。
- 到期检查是确定性规则，不需要调用模型；建议每 5 分钟扫描一次，服务恢复后补检遗漏事项。
- 相同内容、相同规则、同一次到期只生成一个提醒。支持完成、延后、忽略；忽略可附原因。
- 默认只进入后台提醒箱，不自动给访客发消息，不额外创建邮件、飞书等通知通道。
- Agent 后续可提出“这篇内容可能过时”的建议，必须给出证据和原因；站主可以采纳为更新事项，也可以忽略。
- 访客提出的纠错可以进入待核查反馈，不能自动授予后台 Agent 修改权限。拥有持续委托的后台任务也必须独立核查，不能把访客文字当作操作指令。

### 4.7 访客 AI 交互数据与日志（首期）

目标是让站主回答三个问题：访客实际在问什么、Agent 如何回应、哪些需求值得变成内容更新。记录必须同时服务日常运营与故障排查。

#### 4.7.1 收集内容与关联关系

| 数据 | 首期记录内容 | 用途 |
|---|---|---|
| 会话上下文 | 站内随机匿名标识、业务会话 ID、服务位置/部署绑定、来源页面、关联内容 ID 与版本、开始及最后活动时间 | 还原一次互动发生在哪里；不把匿名标识称为真实人数 |
| 逐轮问答 | 访客提交的问题、校验后对外返回的回答、消息顺序与时间、引用、Agent/配置版本、关联请求及运行 ID | 逐轮回看；不能只存摘要导致无法核对回答 |
| 交付状态 | 服务端生成/发出、客户端确认收到、断流/中断、未知；必要时记录实际收到的文本长度 | 区分生成成功和客户端收到，不把收到推断为读过或满意 |
| AI 组件交互 | 介绍展现和关闭、打开入口、提交问题、继续提问、切换 Agent、点击引用、有帮助/没帮助反馈 | 观察使用路径与反馈；不扩大为全站点击流或屏幕录像 |
| 运行日志 | 请求/运行/父运行 ID、SDK 会话 ID、模型、状态、排队/首字/总耗时、已知 token、错误/降级原因、可用工具事件 | 排错、核对资源使用与调度；缺失字段显式标记 |
| 操作日志 | 操作者、动作、目标、版本变化、授权/审批 ID、时间、实际结果 | 核对创建/部署/启停 Agent、授予/撤销权限、内容修改与发布、日志导出与删除 |

- 业务会话由服务端验证归属，SDK 会话 ID 只用于内部关联，不作为访客身份凭据。切换 Agent 可开启新的模型上下文，但在同一业务会话内保留切换事件和各段对应关系。
- 每次发送使用稳定消息/请求 ID；网络重传不重复形成一条新问题，用户明确“重新生成”则产生关联原消息的新运行。统计区分用户问题数与执行尝试数。
- 保存 AI 实际对外返回的版本，包括规则降级回答；未通过校验的模型结果不能混入“访客对话”，诊断信息单独受限保存。
- 流式文本不逐字符重复写成消息；保存有序事件与最终对外文本。断流、截断、未获接收确认明确显示，不伪造完整交付。
- 客户端事件使用唯一 ID 去重、校验字段并限制体积与频率；服务端时间作为接收事实。客户端数据可能缺失或不可信，不据此授予权限或修改内容。
- AI 介绍、入口打开、引用点击等由实际客户端事件证明；“主动介绍展现数”只统计可见组件上报，不把页面加载或后台配置次数算作展现。

#### 4.7.2 后台查看、筛选与使用

- “运营记录”提供“访客对话 / 运行日志 / 操作日志”三个视图；内容详情和 Agent 详情均可进入已筛选的同一批记录，不复制另一套日志。
- 对话列表展示来源内容、时间、轮数、参与 Agent、最后问题、反馈和异常标记；默认最近记录优先，服务端分页。
- 可按日期、内容、服务位置、Agent、会话、运行状态、降级/错误和反馈筛选；支持在保留期内的问题与回答正文中搜索关键词。
- 对话详情逐轮呈现提问、回答、引用、反馈和切换事件；每轮可进入运行日志，错误可由请求 ID 反查。缺失消息或事件显示“不完整”。
- 站主可以将一条问题或反馈关联到更新事项，保留原记录引用；不因访客提出要求就自动改文章、主选题目或发布。
- 按当前筛选范围导出 CSV 汇总或 JSON 明细，导出标明时间范围、字段与记录数；超出单次容量时要求缩小范围，不静默截断。后台列表默认只显示正文摘要，详情可查看已按规则脱敏的正文。
- 概览增加交互会话数、提问数、继续提问会话数、引用点击数和反馈数，能下钻到对应记录。会话数指至少提交过一次问题的业务会话；继续提问指同一业务会话第二次及后续主动提问，排除重传和重新生成。
- 高频问题自动聚类和 AI 总结属于后续增强；首期原始事实、筛选、标记与关联更新事项即可支持人工复盘。

#### 4.7.3 记录可靠性与数据边界

- 正常运行下，服务端接受的问题与完成的对外回答持久保存；失败、拒绝、降级和中断也必须有可区分的结果，不能只记录成功样本。
- 交互日志写入失败不阻断已生成的访客回答，但必须发出可观察的采集异常信号，采用有界重试并标记受影响时间段的数据可能不完整。日志恢复后按稳定 ID 去重补写，不能假称记录从未丢失。
- 授权和内容写入等关键操作不能沿用上述尽力记录策略：执行依据与待执行动作必须先持久化，无法建立可恢复操作记录时拒绝新增副作用。结果回写失败进入待核对流程。
- 运营视图使用持久业务消息记录还原访客对话，Harness 事件保留执行事实，关联 ID 贯通；不依赖随时可能清理的临时进程日志恢复全部对话。
- 对话与日志默认仅经鉴权的站主后台可读。运营 Agent 若需分析原始对话，必须获得单独的数据读取授权；前台 Agent 不得检索历史访客日志。
- 前台首次发送前提供清晰说明：“对话将被记录，供站主改进内容与服务”；不暗中扩展到广告画像、跨站跟踪或其他模型训练用途。
- 匿名标识仅用于站内会话关联，不主动索取真实身份，不默认在运营日志存储完整 IP、Cookie、认证头或任意 URL 查询参数。输入中匹配已知凭据及明显联系方式的内容在持久化前按明确规则脱敏，并标记；不承诺自动识别所有敏感信息。
- 建议正文、可关联访客的事件和诊断明细默认保留 90 天，可由站主缩短；这是本稿产品默认值，不声称所有现有存储已经按此清理。无正文、不可回溯访客的日汇总可单独设置保留期。
- 支持按会话或日期范围删除明细，执行前显示将删除的范围与数量；关联消息、事件、搜索索引、trace 中的正文副本须一并处理。导出副本不承诺远程撤回；备份按保留周期到期清理，恢复后须重放删除记录。
- 日志删除只保留不含对话正文的删除审计，不能借审计无限保存已删除正文；详情区分已删除、已过期、采集失败和从未存在。

## 5. 授权与不可绕过的红线

### 5.1 权限模型

有效权限是“触发来源上限、Agent 允许能力、具体事项授权、对象自身策略”的交集；任一缺失或拒绝，相关动作不得执行。权限由服务端执行点校验，提示词中的要求不构成授权。

| 级别 | 可做什么 | 示例 | 首期支持 |
|---|---|---|---|
| L0 读取与解释 | 在允许范围内读、答、建议 | 文章问答、经营情况解释 | 是；所有前台运行最高到此级 |
| L1 形成候选 | 生成独立候选或计划建议，不覆盖内容正本 | 改稿候选、更新建议 | 是，后台 |
| L2 单次批准执行 | 站主批准具体动作和对象版本后执行一次 | 将确认的候选写入指定文章 | 是，后台；发布仍是独立动作 |
| L3 持续委托 | 在事先明确的职责、对象、动作和期限内自主执行 | 周期扫描提醒；后续可授权指定内容维护与发布 | 首期仅开放扫描与后台提醒；内容自主写入/发布后续实现 |

等级是易读的授权模板，不是万能开关。即使 L3，未勾选的发布/删除动作也不被自动授予；允许“修改”不等于允许“发布”。站主未来可明确授予职责范围内的全部必要动作，无须逐次审批。

授权记录至少包括：站主、Agent 或任务、触发来源、目标对象/范围、允许动作、有效期、运行与用量上限、授权版本、撤销时间。新授权默认单次有效；长期职责须显式选择持续委托。

### 5.2 前台内容写入禁令

- 前台会话不得创建、覆盖、修改、删除或发布站主内容，也不得改项目进度、商品介绍等内容字段。
- 不向前台运行提供内容写工具、发布工具、管理凭据或具备同等效果的文件/命令执行能力。
- 服务端不接受客户端自报“后台来源”“管理员”“已获批准”等权限声明。
- 前台触发的子任务、被调度 Agent 和后续工具调用继承前台只读上限。
- 前台读模型仅暴露已公开且允许 AI 使用的内容；草稿、密钥、内部运行明细与其他访客会话不进入前台上下文。
- 普通站主浏览前台也不能通过对话临时打开写权限；需要进入经过鉴权的后台任务流程。

### 5.3 审批、撤销与并发

- 单次审批绑定候选内容、目标对象版本和动作。批准后候选或原文发生变化，审批失效并展示差异；重复执行同一审批不得重复写入。
- 执行前再次检查权限、有效期、额度和对象版本；排队时有权限不代表执行时仍有权限。
- 撤销授权后拒绝新的副作用动作，停止排队任务；已经提交的写入不被宣称自动回滚，记录其实际结果。
- 多个 Agent 修改同一对象时检测版本冲突，不以最后到达者静默覆盖。
- 对外发布失败或结果不明时先核对已有发布结果；不盲目自动重发。
- “紧急停止”可以禁用 Agent 或服务位置；AI 总开关关闭后访客仍可阅读内容，后台仍可手工运营。

## 6. 运行监督、恢复与资源边界

- 运行记录展示谁发起、在哪个位置、用了哪个配置/内容版本、依据哪次授权、做了哪些可观察动作、产出了什么。
- 展示实际收到的事件与工具调用记录，不伪造模型思维过程；无法提供的步骤或用量标为未知。
- 首期运行状态：排队、运行中、停止中、成功、失败、已取消、状态待核对。待审批属于候选动作状态，不宣称模型进程正在原地等待审批。
- 建议的默认容量为全局最多一个访客运行与一个后台运行，待部署机器实测后确定。Agent 配置数量不等于常驻进程数量；队列有上限，不能无限积压。
- 访客请求沿用现有有界等待与规则降级机制；长后台任务显示排队/运行状态，不占用整个页面等待。
- 取消排队任务可立即完成；运行中停止必须等待实际终止证明，不能只停止页面轮询就标为已取消。
- 已取消/已撤销运行的迟到结果不得写内容、发布或把终态改回成功。
- 服务重启后，从持久记录恢复待办与运行索引；无法证明结果的运行进入“状态待核对”，核验后再允许重试。
- 生产凭据不出现在前台、提示词、可下载运行记录中。新后台会话与日志按 §4.7 的保留、脱敏、导出与删除要求收敛；既有日志存储须纳入迁移核查。

应用负责持久业务状态、授权、调度、预算、审批、对象版本与发布验证；SDK 负责模型运行与可用运行事件。首期候选产出后结束模型运行，审批通过再由受控业务动作提交，减少对运行时交互审批的依赖。

不能直接写入内容库的只读执行环境可先满足前台问答与后台候选生成。若未来要开放模型工具直接写入，须先证明工具执行点也受同一授权约束，再开放 L3 写入职责。

| A22 | 交互采集与去重 | 介绍展现、关闭、提问、反馈、引用点击被正确归属；重复上报相同事件/请求不增加计数，重新生成单列执行尝试 |
| A23 | 失败与交付记录 | 超时、降级、断流和未获客户端确认分别呈现；服务端生成成功不被标为客户端已收到 |
| A24 | 检索与导出 | 可按内容、位置、Agent、日期和关键词找到目标对话，导出范围与筛选一致且经过脱敏，导出操作留痕 |
| A25 | 采集故障 | 模拟日志存储失败，回答仍可返回；后台能观察采集异常与数据缺口，恢复补写不重复计数 |
| A26 | 日志访问隔离 | 未鉴权请求、其他访客及前台 Agent 均无法读取后台对话/运行明细；获授权运营 Agent 只能读取授权范围 |
| A27 | 保留与删除 | 到期或显式删除后正文从业务库、事件/trace 副本和搜索结果消失；保留删除审计，备份恢复不会重新公开已删除数据 |
| A28 | 数据转为运营行动 | 从一条访客问题创建关联更新事项，原内容保持不变；可从事项追到尚在保留期内的对话证据 |

写入红线、授权撤销、版本绑定、会话隔离、真实停止和发布语义是发布门禁；不能以“框架先搭起来”为由略过。

## 9. 演进与文档一致性

首期先完成一篇文章从后台配置服务到前台问答，再经更新提醒回到内容修改的闭环。项目等内容类型复用相同对象与授权机制，不复制另一套 Agent 系统。

后续投入按真实需求触发：多个 Agent 的显式选择不够用时增加自动路由；固定更新职责反复需要审批时增加 L3 内容委托；确有经营商品时定义小店字段与交易边界；采集到足够访客行为后再增加留人效果分析。

与旧文档的差异：

- 旧“计划默认首页/Agent 属于设置”不继承；本稿建议概览首页与独立 Agent 工作面。
- 旧“主选、审批、发布永远人工点击”调整为新系统的设计方向：前台写入永久禁止，后台可按事项授权。首期仍保留内容写入单次审批，L3 内容全权委托未实现前不得开启。
- 旧“后台技能直连 LLM 为主”不作为新 Agent 执行方向；新任务以现有 Harness SDK 为基础。
- 不把旧方案中的已完成项、日期、文章数量或生产声明直接复制成新后台事实。

本文审阅收敛后，应将新后台产品入口与授权规则同步到根 PRD、PLAN、PRODUCT、AGENTS 和架构文档，并明确替代范围。开发改变 API 或部署后再更新契约与 STATUS，避免把拟议能力写成已上线事实。
