# C14：实现发布阶段与幂等脚本调用

## 实施结果

- **发布阶段与持久化状态机（`ContentReleaseRepository.updateStage`）**：
  - 在 `packages/shared/src/content-change.ts` 与 `apps/api/src/ports/content-release.repository.ts` 定义了发布阶段推进契约 `updateStage` 与 `findLatestForTarget`。
  - 在 `PrismaContentReleaseRepository` 实现对 `stage`、`gitCommit`、`manifestHash` 与 `errorCode` 的事务持久化更新，受 `isContentReleaseTransitionAllowed` 状态机保护，禁止非法跳变。
- **阶段流转推进与退出码 0 语义隔离**：
  - 启动发布时将发布记录由 `PREPARED` 推进至 `COMMITTING` 并开始执行发布 runner；
  - 脚本执行成功（退出码 0）后，系统自动读取 Git HEAD commit 记录 `gitCommit`，阶段流转推进至 `PUSHED`，并紧接着转入 `VERIFYING`（线上待核验阶段）；
  - **核心红线落实**：退出码 0 **绝不等于** `PUBLISHED`！因为网站仍需等待 Vercel 静态构建部署与线上真实 hash 核验（留待 C16），发布阶段严禁直接标为 `PUBLISHED`。
- **重复请求幂等复用 release**：
  - 当同一发布处于在途进行中时，重复调用 `service.release` 返回同一个 `runId` 与 `status: 'RUNNING'`，底层发布 runner 调用计数严格为 1，不重复启动子进程。
- **失败保留已完成阶段与已记录事实**：
  - 当子进程非零退出或超时时，阶段更新为 `FAILED`，记录 `errorCode`（如 `release-failed` 或 `release-timeout`），完整保留已生成的 `manifestHash`、`sourceHash` 与已记录的 `gitCommit` 等历史事实。
- **固定命令受控参数与脱敏**：
  - `PnpmContentReleaseRunner` 参数严格固定为常量数组 `['content:publish', '--push', '--json']`，公开文本与用户输入绝不拼接进命令行；输出结构化解析，stderr 经 `redactAbsolutePaths` 脱敏。
