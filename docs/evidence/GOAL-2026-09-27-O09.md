# O09：实现复盘建议显式转下一事项

前置：O08、O03。落点：ReviewEntry→Action 用例/按钮。
动作：站主选中下一次尝试才创建 Action，保留复盘引用和幂等键；不自动选题/发布。
验收：K2/K3；重复点击一条事项，新事项可设置提醒，从事项可回溯原复盘。

## 1. 实现

### 1.1 领域模型与引用关系

- `packages/shared/src/action.ts` 中将 `REVIEW` 加入 `ACTION_ENTITY_TYPES`：
  - 新 Action 的 `entityType = 'REVIEW'`，`entityId = review.id`；
  - 零 schema 迁移（Prisma 中 `Action.entityType` 本身为可空字符串）。
- `Action.source` 固定标记为 `HUMAN`，显式保留复盘事实备注（`源自复盘 {review.id}：{review.didWhat}`）。

### 1.2 服务端用例与接口（`ReminderService` / `ReminderController`）

- `convertReviewToAction`：
  - 严格校验复盘存在且拥有非空的 `nextAttempt`（无下一次尝试建议抛错 `review-has-no-next-attempt`）；
  - 基于 `requestKey` 与审计记录（`action='review.convert', requestId=requestKey`）实现幂等去重；
  - 支持传入 `plannedDate`，复用单一时间规则 `resolveActionDue` 计算 `dueAt`（UTC 瞬时）与 `timezone`；
  - **不自动选题/发布**：仅显式创建 Action，绝不创建 Seed、不触碰发布通道。
- `getReviewForAction`（`GET /ops/actions/:id/review`）：
  - 当事项为 `entityType === 'REVIEW'` 时反向查询并返回原 `ReviewEntry`，实现双向可追溯。

### 1.3 前端面板与交互联动（`ContentReviewPanel.tsx`）

- 每条拥有 `nextAttempt` 的复盘卡片底部渲染「转为下一事项」操作区；
- 支持输入排期日期（`input[type=date]`）；
- 按钮自带独立 `requestKey`，重复点击同一按钮复用该 key，服务端据此幂等回放；
- 界面如实提示：
  - 首次创建：`已创建下一事项：下一尝试：...`
  - 重复点击：`这次转换此前已生效（重复点击未创建第二条事项）`
- 转换成功后，该事项自动进入 `ReminderInboxPanel`（概览与更新提醒），到期可提醒、可完成、可延后、可忽略。

## 2. 验证

### 2.1 K3 真实浏览器端到端核验（Headless Chromium + WebSocket CDP）

在隔离 SQLite 库上启动真实 NestJS API（:8788）与 Vite admin（:5174），播种一条包含 `nextAttempt` 的复盘记录，由 CDP 驱动 Headless Chromium 实测：

```json
{
  "reviewsTabActive": true,
  "seesNextAttempt": true,
  "hasConvertButton": true,
  "convertFeedback": "已创建下一事项：下一尝试：增加交互式示例并再观察一周",
  "replayedFeedback": "这次转换此前已生效（重复点击未创建第二条事项）",
  "newActionInInbox": true,
  "actionDueDate": true,
  "consoleErrors": []
}
```

- 打开 `/records?tab=reviews`，激活复盘标签并定位下一次尝试；
- 填入提醒日期 `2026-10-25` 并点击「转为下一事项」，收到创建成功反馈；
- **再次点击同一按钮**，收到幂等提示「这次转换此前已生效（重复点击未创建第二条事项）」；
- 导航至 `/overview`，确认提醒箱中出现该新事项，且排期日期准确显示为 `2026-10-25`；
- **控制台错误：0 条**。

### 2.2 K2 服务端集成测试（`review-to-action.kernel.integration.test.ts`，6 项全绿）

- 转为下一事项：保留复盘引用（entityType=REVIEW，entityId=review.id），标题源自 nextAttempt；
- 重复点击（同 requestKey）只产生一条事项，幂等回放；
- 新事项可设置提醒日期并推导到期瞬时，扫描后可正常触发 ReminderOccurrence；
- 从事项可回溯原复盘：`getReviewForAction` 准确返回原记录，非复盘事项返回 null；
- 没有下一次尝试的复盘不能转换（抛错 `review-has-no-next-attempt`）；
- 参数校验完整，不自动创建 Seed 或发布。

### 2.3 前端组件测试（`ContentReviewPanel.test.tsx`，7 项全绿）

- 带有 nextAttempt 的复盘正确显示日期输入框与转换按钮；
- 转化提交携带 reviewId、plannedDate 与 requestKey；
- 幂等回放显示「这次转换此前已生效」；
- 重复点击复用相同 requestKey。
