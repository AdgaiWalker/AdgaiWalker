# C05：人工保存受控出口

## 实施结果

- `/admin/content/:slug` 仍由 AppModule 的 `AdminTokenMiddleware` 保护。Controller 要求 `{ raw, expectedHash }`；更新传 GET 返回的正文 hash，新建传 `null`。
- `ContentAdminService` 的 list/get 继续依赖文件仓储；save 改为委托 `ContentMutationService.saveManual`。单站主 actor 固定记录为 `owner`，requestId 由服务端生成，不接受请求体伪造身份。
- Manual save 在 R05 `OperationsJournal` 事务中先写 intent audit，再执行 C03 文件 CAS，随后独立写完成/冲突/失败结果 audit。审计只记录 slug、requestId、actor 和 before/after hash，不保存正文或管理凭据。
- intent 审计不可用时返回 `content-audit-unavailable`，正文不会写入；CAS 冲突写 conflict audit；完成审计失败时返回 `content-save-audit-unavailable` 并明确说明正文已写入但审计确认未完成，intent audit 保留。
- 移除了 `ContentAdminService` 的 `pnpm content:gen` 子进程调用；人工保存不会改变 public `content.json` / 快照，也不创建 `ContentChange`，不要求模型批准。人工工作区保存仍不等于发布。

## 验收边界

- 人工保存和文件写入后审计仍是两个事务；若结果审计事务失败，调用方收到错误并看到正文已经写入、审计未确认，不会被告知为未保存。
- 该出口覆盖管理端人工保存，不代表旧工作站或其他内容写入旁路都已封闭；C11 继续清点这些路径。
- 没有 schema migration，没有改 `content/log` 正本，未触发模型或部署。
