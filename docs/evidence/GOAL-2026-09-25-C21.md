## 1. 目标与实现内容

依据 PRD A8/A9、TECH-DESIGN §6.2 与原子清单 C21 要求，将旧工作站网站发布流程（`PublicationService`）接入统一的 `ContentRelease` 出口：

1. **保留候选 hash 审批与作品状态流转**：
   - 严格保留作品的候选产物审批机制：`work.approvedArtifactHash !== artifactHash` 或与 `REVIEW_READY` 产物不匹配时直接抛出 `artifact-hash-mismatch` 异常。
   - 严格保留作品生命周期状态推进：初稿审批通过为 `APPROVED`，发布验证成功推进为 `PARTIALLY_PUBLISHED`（若微信已发布则推进为 `COMPLETED`）。

2. **拒绝范围外内容提交（范围冲突防御）**：
   - 在 `publishWebsite` 流程中，写盘前后均经由 `ContentReleaseService.preflight(slug)` 门禁与提交范围预检：
     - 若存在未提交的代码改动（`code-dirty`）、未提交的 `support-config.json`（`support-config-dirty`）或存在未提交的其他文章（`other-content-dirty`），立刻拒绝发布并抛出 `ApiError('scope-conflict', HttpStatus.CONFLICT)`。
     - 若公开必需字段缺失，同样阻断并报错，绝不将范围外脏文件夹带上线。

3. **发布动作引用 ContentRelease 与事实记录**：
   - `publishWebsite` 调用 `this.contentRelease.prepareRelease` 生成不可变 `ContentRelease` 事实记录（绑定 `publish-website` 动作、L2 授权审批 `publishApproval` 与正本目标 SHA-256）。
   - 恪守诚实原则：`publishWebsite` 仅落盘正本到 `content/log` 并创建关联的发布单，`Publication` 记录状态如实保持为 `PREPARED`，**`PREPARED` 仍不等于 `PUBLISHED`**。

4. **线上核验出口收敛，不另起 Git / 核验链**：
   - `verifyWebsite` 优先复用统一的 `ContentReleaseService.getLatestRelease(slug)` 与 `verify(latestRelease.id)` 出口。
   - 只有在线上确证目标版本（或底层发布单已确证为 `PUBLISHED`）时，`Publication` 状态才更新为 `PUBLISHED`；否则标记为 `FAILED` 并记录确切失败原因。
   - 旧控制器与旧端点（`POST /works/:id/publish/website` 与 `POST /works/:id/publish/website/verify`）保持作为适配薄层，底层完全收敛至 `ContentRelease`，彻底消除发布旁路。
