# V21：受控导出与下载

## 目标与边界

从 V20 的访客会话筛选页创建 CSV 汇总或 JSON 明细导出。任务创建时冻结筛选条件、明细保留截止和匹配会话 ID 集；最多 10,000 个会话，异步生成。下载需管理鉴权，文件在本机保存 15 分钟。导出文本二次复用 shared 脱敏规则，CSV 对表格公式前缀转义。删除任一入选会话时清除整份本机导出；已下载到外部的副本无法远程撤回。

实现未公开 `/ops`，没有部署生产，也没有声称能撤回外部文件。10,000 行实际压力、满盘故障和 Windows/生产 ACL 尚未实测。

## 实现摘要

- `POST /ops/exports` 使用 V20 同一服务端筛选解析和 SQL 条件，捕获 `snapshotAt`、当前 detail cutoff 和稳定顺序的会话 ID。超过上限返回 422，不静默截断。
- Job 使用 SQLite `ConversationExportJob` 持久化格式、状态、脱敏筛选快照、快照时间、保留截止、行数和安全错误码。任务由单 worker 队列生成；启动时恢复未完成任务，并清理临时文件/无 READY job 对应的孤儿文件。
- CSV 先输出等宽 metadata 行（快照时刻、保留截止、脱敏筛选和实际会话数），再输出一会话一行的摘要；JSON 输出 V20 详情并在 metadata 中标记字段。逐轮消息、交互和新增消息按 `snapshotAt` 过滤。所有字符串应用 `redactSensitive`；CSV 全字段引用并对 `= + - @` 公式前缀加文本标记。
- 私有本机目录默认为 API cwd 下的 `data/exports`，可用 `WALKER_EXPORT_DIR` 覆盖。文件名由 opaque job ID 和格式推导；写入临时文件后同步并 rename，不向 API 返回文件路径。
- 到期时间由 `snapshotAt + 15 分钟` 运行时计算，文件大小在打开下载时 stat；两者都不复制进 Job 表。到期、已撤销或文件缺失时下载返回 410。
- 每条入选会话通过现有 `ConversationLogResource` 关联同一个导出 job。删除流程先清本机文件，再撤销 job 并清除该 job 所有资源关联。普通 90 天日志清理跳过 `export`，由独立 TTL 负责失效；任一下载副本已离开本机后不宣称可撤回。
- 创建、下载授权、失败、过期和撤销写入现有 `AuditRecord`；审计不保存筛选文本、问题或回答正文。
- Admin 访客对话面板提供 CSV/JSON 按钮、任务轮询、快照字段/范围/行数/截止时间展示和带内存管理凭据的下载。图标来自 Lucide。

> Design principle: 持久化使导出可恢复、可撤销、可审计所必需的快照事实；到期时间、路径和文件大小由快照或本机文件推导。

### 3. Runtime Fields

- `expiresAt`: `snapshotAt + 15 分钟` | source: `ConversationExportJob.snapshotAt` | computed: API 响应、worker/下载有效性检查。
- `filePath`: `resolve(WALKER_EXPORT_DIR || <API cwd>/data/exports) / <job id>.<format>` | source: 私有目录配置、job id 与 format | computed: 文件写入/打开/清理时；不接受客户端路径。
- `byteLength`: 文件 stat 的当前长度 | source: READY 本机文件 | computed: 下载打开时；不存入 SQLite。
- `downloadPath`: Job 处于 READY 时按 ID 组装 `/ops/exports/:id/download`，其他状态为 null | source: Job 状态与 ID | computed: API 响应。
- `fields`: 由 CSV/JSON 形式对应的服务端字段常量决定 | source: 导出格式 | computed: API 状态响应。

### 5. Change List

- **New fields/table**: `ConversationExportJob(id, format, status, filters, snapshotAt, retentionCutoff, rowCount, errorCode)` 与索引；迁移 `20260925150000_conversation_exports`。
- **Renames**: none。
- **Removals**: `expiresAt` 不落库（由 `snapshotAt+TTL` 推导）；`byteLength` 不落库（由文件 stat 得出）；不增加完成时刻或绝对路径字段。
- **Moves**: none。
- **Related entity**: 复用 `ConversationLogResource`；按每个命中会话登记 export 资源及 `parentKey=jobId`，普通 retention cleanup 对 export 类型跳过。
- **API gaps**: none；创建、状态、下载均为受管理鉴权的 `/ops/exports`。

### 6. Design Decisions

| Decision | Reasoning |
|----------|-----------|
| `filters` 用 JSON，而不是 7 个列 | 创建后不再依这些字段查询/排序；筛选字段可随 V20 演进，不需要每加一项就迁移。范围由每会话资源行冻结。 |
| `rowCount` 单独存列 | Job 过期/撤销或入选会话删除后资源行会清除，原本匹配数量仍需在状态页保留。 |
| `expiresAt` 不存列 | 固定 15 分钟策略下它是 `snapshotAt` 的纯函数；新增列会重复真相且可能漂移。 |
| `byteLength` 不存列 | 可由文件系统 stat 直接计算；元数据不会改变任务可用性。 |
| 不建 `ConversationExportItem` | `ConversationLogResource` 已是资源 ↔ 会话删除索引，新增 join table 会重复关系并增加双删职责。 |
| Job 筛选值在删除撤销/到期时清空 | 避免被删会话或过期导出的关键词/内容范围长期留在任务元数据；审计只保留 job ID 和无正文 outcome。 |
