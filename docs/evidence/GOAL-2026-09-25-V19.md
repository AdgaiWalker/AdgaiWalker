# V19 删除清单与备份恢复防复活

## 目标与边界

恢复任一有效 SQLite 备份时，先把备份之后发生的删除事实重放到目标库，再清理 tombstone 会话和到期资源；全部成功前 API 不监听。恢复失败保留恢复门，不能跳过清理开放服务。

实现及测试均为本地结果，生产未部署。旧快照 K6 使用真实 SQLite 文件做了回放验证；Windows PowerShell、腾讯云任务、Gateway、异机/对象存储恢复没有在当前 macOS 环境运行。

## 实现

- `FsDeletionManifestStore` 将 tombstone ID、Conversation ID 和请求时间以原子替换写入 `control/deletion-manifest.json`，不含正文、路径或匿名明文。每次 V18 删除必须先持久化清单，再进入 stop/cleanup；清单写入失败将任务置为 `blocked`，不清正文。数据库和清单同时有 tombstone 时幂等合并；格式损坏、重复 ID、过大清单或所有清单副本都不可读均 fail-closed。
- 配置 `WALKER_DELETION_MANIFEST_REPLICA_PATH` 后，写入本地控制清单后还必须同步到配置副本；副本不可写时删除不获准继续清理。若需要整机故障恢复能力，必须把该副本指向独立可用存储，或在每次删除后把最新清单复制到盒外。当前没有云存储连接，未声称已配置盒外副本。
- `DeletionManifestReplayService` 把缺失删除墓碑重建为 `pending`；restore marker 存在时强制重开所有清单项，即使备份内旧墓碑标为 `completed`。仅在清理后才写不含正文的 `conversation-delete-replayed` 审计；同一墓碑用稳定审计 ID 去重。清理仍复用 V18 `ConversationDeletionService` 和既有资源 adapter。
- API 启动流程在 `app.listen` 前依次重放删除清单、恢复待删 tombstone、清理后台运行保留期和到期日志资源，并核验恢复清单全部 `completed`。进程级 `WALKER_STARTUP_RECONCILIATION` 暂停队列派发。`restore.pending` 存在时所有 API 请求返回 503；成功后才移除标记并监听，失败则退出并保持标记。
- `LogRetentionCleanupService` 按会话走 V18 整体删除，未归属会话的到期资源走 V17 resource adapter；任何资源清理错误都使启动失败。独立到期的 ownerless ExecutionRun/Event 也通过同一 repo 清理逻辑删除。
- `log:maintenance snapshot <db> <manifest>` 使用 SQLite `VACUUM INTO` 生成一致快照，检查数据库完整性/外键，导出墓碑清单，并记录数据库/清单哈希与 30 天 `expiresAt`。`merge <manifest>` 将外部最新清单并入本机及已配置副本；`verify-db <db>` 校验隔离数据库。
- `ops/windows/backup-walker.ps1` 负责停 API/Gateway、生成快照、核健康后恢复 Gateway；`restore-walker.ps1` 校验文件 hash 和 30 天期限，要求提供最新删除清单，先立门标记、停服、迁移和检查临时库、替换数据，再启动 API 等启动清理完成，最后才启 Gateway。失败保持 marker 且两个任务停止。临时回滚快照也带同一到期元数据。

备份策略：全量 SQLite 备份有效期 30 天；超过期限的备份会被恢复脚本拒绝，盒外存储生命周期应同样设为 30 天。删除清单没有正文，保留时间不得短于任何仍可恢复备份。只恢复旧快照配套清单不能证明包含该快照之后的删除，异机恢复必须提供最新的盒外清单；当前没有自动云同步，站主需提供这份外部状态。

## K6 与测试证据

- `conversation-deletion.restore.integration.test.ts` 创建含访客正文的 SQLite 快照，快照完成后在源库删除正文并写恢复清单，再把旧文件复制为恢复目标。真实 Prisma 目标库导入墓碑并经 V18 删除服务清理；断言目标 Conversation/Message 不存在、tombstone 为 `completed`、恢复审计无正文。源库删除与目标旧备份之间确有文件时间差，不是只在同一 DB 回滚状态。
- `log-maintenance.cli.test.ts` 验证快照可重开、`integrity_check=ok`、SHA-256 匹配且到期时间为创建后 30 天。
- `deletion-manifest-replay.service.test.ts` 覆盖从缺失墓碑的旧库导入 pending 状态、旧库仍含正文时不提前宣告完成、完整删除审计去重以及已完成墓碑遇到恢复数据后重开。
- `restore-gate.test.ts` 覆盖门标记存在时 503、清除后放行；V18 集成覆盖会话资源删除和 spool 防复活；retention 测试覆盖到期清理失败不降级放行。
- 13 个 V19 定向 API 测试文件/53 项通过；全量 API 95 文件/469 项、shared 41/327、web 39/226、agent 5/30 全部通过。`pnpm typecheck` 与 `pnpm build:api` 通过。CLI `verify-db` 对隔离 `walker.test.db` 的实际入口调用通过。

PowerShell 封装、Windows 文件锁、计划任务、Caddy、网络副本和正式 30 天过期拒绝路径未在 Windows 实际执行；本轮不做生产恢复或部署。

## Hai TDD 记录

### 目标行为

删除正文前把无正文恢复清单写到稳定位置；清单或副本写入失败时清理不继续。恢复入口把旧备份会话重新标为待删，并在资源清理、到期清理和清单核验完成前不开放 API。

### RED

- `fs-deletion-manifest.store.test.ts` 先引用缺失 adapter，命令 `pnpm --filter @walker/api exec vitest run src/adapters/fs-deletion-manifest.store.test.ts` 因目标模块不存在而失败；新增幂等落盘/重启读取与损坏清单 fail-closed 行为。
- `conversation-deletion.service.test.ts` 新增清单写失败用例，实际响应仍为 `completed`、无错误码，证明删除服务忽略恢复日志失败。
- `deletion-manifest-replay.service.test.ts` 和 `log-retention-cleanup.service.test.ts` 分别因目标 service 不存在而失败。
- `restore-gate.test.ts` 因缺少门 middleware 而失败；测试要求门文件存在时不能进入 handler。
- 写入可选副本后，针对副本不可用的用例先实际返回成功，证明 API 仅依赖本机清单还不满足配置了远端副本时的 fail-closed 合同。

### GREEN

- 原子 JSON 清单 + 可配置副本；V18 deletion 在 manifest record 失败时保留 tombstone 并阻断删除。
- 恢复 service 重建 tombstone/审计，retention service 对会话资源和 ownerless 文件/DB 资源进行清理；门 middleware 只在 marker 不存在时放行。
- API main 在 `listen` 之前执行 replay、待删任务恢复、运行到期清理和日志到期清理；restore 模式要求 manifest 全部完成。执行调度泵在该阶段关闭。
- 因 Prisma 当前 SQLite connector 不支持 `createMany(skipDuplicates)`，恢复审计采用稳定 ID 的显式查重；测试真实捕获并修正该实现错误。
- 13 个定向 API 文件/53 项通过；包含真实 `VACUUM INTO` 旧快照回放的 SQLite 集成通过。

### REFACTOR

- 是：API 和快照命令共用 `loadApiEnvFile`；定期清理复用 `ConversationDeletionService`、V17 resource adapter 和现有 deletion repository，避免第二套删除分支；文件清理类型集合由删除 service 导出复用。
- 全量 typecheck、API/shared/web/agent 套件与 API 构建均通过。
