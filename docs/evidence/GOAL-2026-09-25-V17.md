## 目标行为

每个会话正文副本和持久运行资源都能按业务会话枚举；资源登记不保存任意文件路径。明细与不可回连聚合有各自保留期，过期时间根据资源创建时间和当前政策计算，因此缩短政策后资源可以立即进入到期候选。tombstone 先于后续删除阶段存在，并阻止新资源登记把资源重新挂回已标记会话。

## 实体模型审计

> 设计原则：持久化稳定逻辑 ID 和归属；位置由固定 adapter 推导，到期时间由可变策略计算。

## 2. Config Fields

没有 JSON 配置 blob。保留天数是单行系统配置表字段：后台需要校验上限、服务端据此分支选择到期资源，因此保留为独立整数列。

## 3. Runtime Fields

- `expiresAt`: `resourceCreatedAt + retentionDays(resourceType)`；来源是资源表与 `LogRetentionPolicy`；在资源列表/过期选择时计算，不持久化。
- `expired`: `expiresAt <= now`；来源是上一个派生值与查询时钟；查询时计算。
- 文件实际位置：由 resource type + key + 服务端配置根目录推导；数据库/API 不保存或返回绝对路径。
- spool 待回放项：V16 队列文件中的 `eventId`、`conversationId`、`queuedAt` 自身构成临时资源登记；服务按会话读取队列元数据，无需在数据库不可用时双写登记表。

## 5. Change List

- **New fields/tables**：新增 `ConversationLogResource`、`DeletionTombstone`、`LogRetentionPolicy` 及到期/归属索引；迁移回填现有 Message、FeatureEvent、AssistantRun、ConversationSdkSession、ExecutionRun 和 ExecutionEvent。
- **Registration**：消息、事件、助手历史、统一执行输入/输出、原生 session 与 trace 在来源写入事务/入口处登记；spool 通过其文件记录登记；未来 export 可调用同一资源接口。
- **API**：新增鉴权管理路由读取/更新保留期限、按会话枚举资源、选择到期资源；接口不收路径、不返回底层 key。
- **Runtime-only**：`expiresAt` 与 `expired` 不写入每条资源；策略缩短后无需重写资源行。
- **Migration**：使用新 SQLite migration；未连接生产或开发库进行迁移。

## 6. Design Decisions

| Decision | Reasoning |
|----------|-----------|
| `conversationId` 不建外键 | 删除 Conversation 行后还需要 tombstone/resource rows 找到所有副本；级联删除会先销毁清理索引。 |
| `resourceKey` 不叫 path，也不存绝对路径 | 数据库只存来源稳定 ID。trace、spool、native session 和导出文件的实际位置由对应 adapter 在服务端配置根目录下推导。 |
| 唯一键为 `(resourceType, resourceKey)` | 同一来源资源只有一个 owner；重试可幂等登记，owner 冲突会失败关闭。 |
| 不存 `expiresAt` | 到期日期取决于可缩短的当前政策；冗余保存会在政策变化后漂移。 |
| 聚合默认 365 天，明细 90 天 | PRD 要求分开设置但未给聚合具体值；采用一年作为不可回连汇总默认，并允许缩短。 |
| spool 不双写数据库登记 | spool 正是数据库不可写时的承载；每个 JSON 事件文件已有 eventId/owner/queuedAt，可在数据库恢复后登记对应 FeatureEvent。 |
