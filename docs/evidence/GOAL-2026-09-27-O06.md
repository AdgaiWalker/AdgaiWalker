# O06：实现可追溯的运营统计

前置：V20、V15、O03。落点：OperationsService 聚合、`/ops/overview`。
验收：K2；重复事件/重新生成不抬高提问数，缺 usage 不计 0，不制造没有分母的留存率/转化率。

## 1. 实现

### 1.1 口径只有一份（shared `ops-stats.ts`）

三条诚实纪律全部写成纯函数，服务端只做取数与组装，**不在 SQL 或服务里另写一套判定**：

| 函数 | 职责 |
|---|---|
| `countAsks` | 提问数 = **唯一访客消息 id 基数**（Set 去重）；`regenerationAttempts = Σ max(0, attempt数-1)` |
| `countAnswers` | 成功 / 降级 / **失败** / 未知 四类互斥分开；交付确认（`delivery=ack`）独立于生成成功 |
| `summarizeUsage` | 只累加**明确记录**的用量；一条都没有 → `null` + `coverage`；明确记 0 仍是 0 |
| `rateOrNull` | 分母 ≤ 0 或非有限数 → `null`，不造比率 |
| `resolveStatsWindow` | 三个窗口（24h/7d/30d）的区间与小时数 |

### 1.2 关键修正：失败绝不算成功

初版 `countAnswers` 忽略 `state`，导致 **`FAILED` 的运行被计入「降级但可用」**——那是在粉饰失败。改为先判状态：`FAILED`/`CANCELLED` → `failed`；`UNKNOWN` 或缺 `aiUsedFlag` → `unknown`；只有 `SUCCEEDED` 且 AI 实际产出未降级才算 `succeeded`。

### 1.3 取数：每个数字都写得出来源

`provenance.sources` 逐条声明口径出处（ConversationMessage / ConversationTurn+Attempt / AssistantRun+delivery / ExecutionRun.tokens / Action+ReminderOccurrence / ContentChange+ContentRelease）；`provenance.missing` 声明缺口与覆盖比例。窗口缺省 `7d`，**非法窗口值回落默认而不报 500**（不因一个查询参数丢掉整个概览）。

## 2. 验证

### 2.1 shared 单元测试（`ops-stats.test.ts`，12 项）

重复消息 id 去重（`m1,m1,m2` → 2）；**重新生成只增 `regenerationAttempts`**，提问/会话/轮次全不变；四类互斥且**合计 = 运行总数**（没有一条被丢掉或重复算）；缺 `aiUsedFlag` → `unknown`；交付确认 < 生成成功；**全缺失 → `null` 且 coverage=0**；**零运行 → coverage=`null`**；部分缺失只累加已知并用 coverage 说明缺口；**明确记 0 仍是 0**；分母 0 → `rateOrNull` 为 `null`；三窗口区间长度精确。

### 2.2 K2 Kernel 集成测试（`operations-stats.kernel.integration.test.ts`，9 项）

造真实会话（含 2 次 attempt = 1 次重生成）与运行（1 条带用量 100/50、1 条无用量、1 条 `FAILED`）：

- 提问数按唯一访客消息计（2 条）；重生成数正确（1）；
- **再补 2 次重生成后，提问/会话/轮次一字不变**，只有 `regenerationAttempts` 上升；
- `usage.runsWithUsage=1`、**`coverage` 严格介于 0 与 1 之间**（证明缺失的运行**没有**被当成 0 计入，否则覆盖率会是 1）、总量恰为 100/50/150；
- 端到端与纯函数双路核对「一条用量都没有」与「一条运行都没有」两种情形；
- `provenance` 的窗口长度精确为 24h、来源 ≥ 5 条且含表名、`missing` 含 `usage` 与 `answerOutcome`；
- 非法窗口回落 `7d`；提醒/内容计数与直接查库一致；**窗口外事实不被计入**。

### 2.3 HTTP 实测（隔离库 + 真实 token）

| 检查 | 结果 |
|---|---|
| 匿名访问 | **401** |
| 正确 token | **200** |
| 空库 | 全部计数 0，`usage.totalTokens=null`、`coverage=null`（**不造假**） |
| 有数据 | `open=3`、`overdue=3`；`usage.runs=3`、`runsWithUsage=1`、`coverage=0.333…`、`tokensIn=300`、`total=420`（**缺失运行未计 0**）；`answers.failed=1`、`succeeded=0`、`unknown=2`（**失败没被算成成功**） |

> 核验中发现：Prisma 在 SQLite 把 DateTime 存为**整数 epoch**，我最初用手写 SQL 播种时写成了文本，导致窗口查询读不到。这是我的核验脚本问题，不是产品缺陷；改用 Prisma 正确格式播种后统计全部正确。此坑已记录，后续手工造数据一律经 Prisma。
