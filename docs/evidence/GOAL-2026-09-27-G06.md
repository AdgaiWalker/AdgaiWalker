# G06：准备可恢复的部署包与执行顺序

前置：G05。落点：`ops/windows/README.md`、部署/迁移脚本与回退说明。
动作：固定代码/SDK/runtime/迁移版本、备份和删除清单、停服释放引擎顺序、能力关闭默认值；安排 manifest 基线构建先于新公共问答启用。
验收：K0/K6；隔离演练部署/回退可执行；现有 content dirty 检查、持久目录不覆盖、公开双白名单均保留；不靠旧无授权写路径回退。

## 1. 发现并修复的真实缺陷：SDK 版本两处漂移

`ops/windows/install-dsh.ps1` 硬编码 `@deepseek-ai/dsh@0.1.2-alpha.3`，而 `apps/api/package.json` 已钉到 `0.1.5-rc.3`。

**为什么这是真缺陷而非文档瑕疵**：adapter 要求 SDK 与 dsh 运行时同版本，不同版本会**拒绝启动**（`scripts/sdk-version.ts` 顶部已记录该约束与「改版本号不等于可用」的实测教训）。照旧脚本装机，助手 runtime 直接起不来。

**修复**：`install-dsh.ps1` 改为从 `apps/api/package.json` 派生版本（`$PSScriptRoot` 上溯两级 → `apps\api\package.json` → `dependencies.'@deepseek-ai/dsh'`），只有一个真相源，杜绝再次漂移；缺失版本时直接抛错而不是装错版本。保留 UTF-8 BOM。

## 2. 新增机器门禁 `pnpm verify:deploy`（K0）

文档检查表会漂移，所以把部署包不变量变成可机检断言，**失败即拒绝发版**。15 项检查：

| 类别 | 检查 |
|---|---|
| 版本固定 | dsh 家族 23 个包版本唯一（`0.1.5-rc.3`）；安装脚本不硬编码版本；安装脚本确实读 package.json；探针报告 SDK 版本与代码一致 |
| 迁移清单 | 24 个迁移命名唯一且有序；`migration_lock.toml` 存在 |
| 能力默认关闭 | `.env.example` 与部署文档样例均 `AI_ENABLED=false` |
| content dirty | 脚本存在 + 部署文档要求拉代码前先跑 |
| 持久目录 | 备份/恢复脚本存在 + 文档声明 data 不被覆盖 |
| 公开双白名单 | `compareCaddyPublicRoutes(Caddyfile)` 与 Nest exclude 逐方法完全一致 |
| 回退纪律 | 文档明确禁止回退到旧无版本写路径 |

**检查范围的一处自我修正**：初版把 `@deepseek-ai/cordis*` 也纳入同版本比对，误报「出现多个版本」。实际上只有 `dsh` 家族（SDK 与运行时）必须同版本，cordis 插件各有独立版本线（4.0.2 / 1.0.17 / …）；已收窄为 `/^@deepseek-ai\/dsh(\b|-)/`。

## 3. K6 隔离演练（可执行，非纸面）

`pnpm verify:deploy --drill` 在临时库上真实执行「迁移 → 备份 → 回退」往返：

```
✓ 迁移：24 个迁移在隔离库全部应用
✓ 备份：VACUUM INTO 生成快照（45 张表）
✓ 回退：快照恢复后 45 张表一致，未走任何旧写入接口
✓ K6 隔离演练通过（迁移 → 备份 → 回退往返）
```

演练在 `os.tmpdir()` 建库、结束即删；备份用 SQLite 原生 `VACUUM INTO`（不是文件拷贝——拷贝会拿到撕裂页），与 `backup-walker.ps1` 同思路。**全程不接触开发库**。

## 4. 部署包文档（`ops/windows/README.md` 新增「部署包与执行顺序」）

- **版本固定表**：代码版本（`git short SHA` → `WALKER_BUILD_VERSION`）、SDK/runtime `0.1.5-rc.3`、Node 22+、24 个迁移（最新 `20260927110000_execution_run_legacy_source`），每项标注真相源；
- **发版前门禁**：`pnpm verify:deploy` / `--drill`；
- **停服与释放引擎顺序**：`schtasks /End` → 核 8788 真释放 → `db:generate` → `build:api` → 写版本 → `/Run`（不可调换，运行中 generate 必 EPERM）；
- **能力关闭默认值表**：AI / 公共位置 / 内容发布三项默认关闭与开启方式；小店交易、外部实时追踪、自动多 Agent 接力、持续全权委托标注**首期未接入**；
- **执行顺序含 manifest 基线**：停服备份 → 构建 → **先 `pnpm snapshot:import` 建立 manifest 基线** → 再逐位置启用公共问答（就绪门 + 内存余量门全绿）→ 最后才开 `AI_ENABLED`。理由写进文档：问答索引只认已核验快照，基线没落地就启用等于让访客问答跑在未核验内容上；
- **备份与删除清单**：必须备份（`walker.db`、`admin-basic-auth.txt`、`public-snapshots`、`runs`）/ 可以删除（`logs`、dsh 会话缓存）/ **绝不删除**（库与凭据）；
- **回退说明**：优先关闭能力而非回滚代码；**禁止**回退到旧的无版本/无权限写路径（会绕开 CAS、审批与审计，等于重开已封闭的写入旁路）；前端回退不删新增数据；数据库扩展式迁移可向前兼容读取；恢复前服务保持 503（`restore-reconciliation-pending`），不开放不可信状态。
