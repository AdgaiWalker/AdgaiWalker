# O05：实现访客问题转更新事项

前置：O01、V20、V18。落点：conversation→Action 用例、records 详情按钮。
验收：K2/K3；可从事项追到保留期内证据，删除/过期显示证据不可用；转事项不授予 AI 内容写权限。

## 1. 实现

### 1.1 证据是**软引用**，不是外键（关键设计）

新增 `Action.evidenceRef`（可空 JSON 列，迁移 `20260927100000_action_evidence_ref`）：`{ conversationId, messageIds, capturedAt }`。

**为什么不加外键**：加了外键只有两条路——级联删除（访客删会话时连带删掉站主建的事项）或 `Restrict`（阻止访客行使删除权）。两者都不可接受。软引用让事项**保留**，同时如实标注证据已不可用。`messageIds` 只保留该会话内真实存在的消息 id，伪造 id 被丢弃。

### 1.2 三条红线

1. **显式操作**：只有站主点「创建事项」才落库；不存在任何把访客问题自动变成任务的路径。
2. **不复制会话**：事项上只有站主确认过的标题（摘要，上限 500 字符）+ 软引用。**助手回答不被引用**（默认只取访客问题）；事项自身不含会话正文（正文只在会话表里）。
3. **不授予 AI 写权限**：用例只写 `Action`，不创建授权、不产生内容候选。有测试直接断言 `AuthorizationGrant` 与 `ContentChange` 计数不变。

### 1.3 保留期口径复用既有服务

`loadConversation` 走既有 `ConversationQueryService.detail`（records 页面同一入口），**不另写一套过期判断**。过期会话无法被转成事项；已转的事项过期后回看证据返回 `expired`。删除判定用既有 `DeletionTombstone`。

### 1.4 幂等与预览

- `GET /ops/conversations/:id/action-preview` 零写入；摘要复用 shared `summarizeVisitorQuestion`（不另写一份截断逻辑）。
- `POST .../action` 以 `requestKey` 幂等（审计行 `conversation.convert` + `requestId`，与 O03 同一约定，不另建表）。
- 排期复用 `ReminderService.resolveDue` → 共享时间规则，不重算偏移。

### 1.5 界面

对话详情页新增 `ConversationActionPanel`：摘要预填可改、可选提醒日期、说明「只保存摘要与引用 / 会话删除后显示证据不可用 / 不授予 AI 写权限」。成功即换新 `requestKey`（下一次是真正的又一次显式操作），重复点击则复用同键并由服务端回放。

## 2. 验证

### 2.1 K2 Kernel 集成测试（`conversation-action.kernel.integration.test.ts`，11 项）

预览零写入（`action` 计数不变）；转事项只存摘要与引用、**标题不含访客原话、不含助手回答**；**幂等**（同键重放同 id，该会话只对应 1 条事项）；**保留期内证据可取回**且只有访客消息；**删除后 `reason='deleted'` 且事项仍在**；**过期后 `reason='expired'` 且不回填旧正文**；过期会话无法被转事项；伪造消息 id 被丢弃；**不授予 AI 写权限**（授权数与内容候选数均不变）；参数校验；排期沿用共享规则（`2026-10-15` → `2026-10-14T16:00:00.000Z`）。

### 2.2 发现并修复的真实缺陷

加入 O05 测试后，**全量 API 套件出现两处失败**：`log-maintenance.cli.test.ts`（SQLite 快照）与 `conversation-deletion.restore.integration.test.ts`（恢复核对）。

根因不是被测代码，而是**我的新测试泄漏了状态**：删除用例在共享测试库里建了 `DeletionTombstone` 却未清理，而这两个测试会把整库当作全局事实来快照/核对。修复为在 `afterAll` 中按会话 id 清除墓碑。

修复后**连续三次全量套件 133 文件 / 652 项全绿**。此前记录的「批量顺序敏感」疑点由此得到解释与消除——不是既有测试不稳定，是新测试污染了共享库。
