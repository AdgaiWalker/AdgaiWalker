# C15：将版本证明写入网页构建

## 实施结果

- **公开 Manifest 关联 Git 标识与内容哈希（`scripts/generate-content.ts`）**：
  - 构建内容时，自动执行 `git log -1 --format=%H` 读取当前 HEAD 提交，并将 `gitCommit` 写入 `public-manifest.json`；
  - 维持 `buildId`、`collectionHash` 与单篇条目 `hash` 的确定性计算；
  - **同标题改正文能区分版本**：文档内容哈希由纯内容数据集合经 `stableJson` 序列化后生成 SHA-256 签名，标题相同但正文改动的文章必定产生不同的版本哈希，杜绝仅靠标题识别版本造成的混淆；
  - 清单仅包含公开属性（`slug`、`title`、`summary`、`updated`、`hash`、`readable`、`citable`），绝不泄露内部未公开的诊断细节。
- **版本证明注入文章 HTML（`scripts/prerender-web.ts`）**：
  - 预渲染脚本导入 `public-manifest.json`，提取每篇公开文章的真实 `contentHash`、`buildId` 与 `gitCommit`；
  - 在每篇预渲染 HTML 的 `<head>` 中注入专属版本元数据标签：
    - `<meta name="content-hash" content="..." />`
    - `<meta name="build-id" content="..." />`
    - `<meta name="git-commit" content="..." />`
  - 在文章 DOM 结构中注入属性 `<header data-content-hash="...">`，同时保持外层字面量 `<article>` 满足 GEO 门禁校验；
  - 在构建后将 `public-manifest.json` 自动复制到 `apps/web/dist/`，供外部核验器及快照同步直读。
- **公开图谱规则不分叉**：
  - 知识图谱抽取引擎（`packages/shared/src/graph.ts`）与 `public-manifest.json`、`content.json` 共享同一份解析管道，双向图谱节点与边规则完全一致，无分叉逻辑。
