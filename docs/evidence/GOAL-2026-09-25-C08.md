# C08：实现后台生成内容候选

## 实施结果

- **候选提议契约与接口**：
  - 在 `apps/api/src/ports/content-mutation.port.ts` 定义了 `ContentProposeInput` 与 `ContentMutationPort.propose`。
  - 在 `apps/api/src/ports/content-change.repository.ts` 与 `PrismaContentChangeRepository` 中增加了 `list(filter?: { slug?: string; limit?: number })` 候选列表查询能力。
- **受控提议生成业务逻辑（`ContentMutationService.propose`）**：
  - **固定正文版本**：读取当前正本正文，固定基线 `baseHash`，正本文章在整个流程中保持只读，hash 绝不改变。
  - **强制 L1 授权校验（R09）**：通过 `grantAllows` 校验调用方必须持有针对该目标文章且包含 `content:propose` 动作的有效未过期 L1 授权。
  - **调度 Agent 执行（R15）**：通过 `AgentExecutionService.accept` 提交 `kind: 'file'` 的后台运行任务，模型运行无论成功还是失败均产生 `ExecutionRun` 持久记录与事件轨迹。
  - **坏输出防御**：
    - 模型运行失败时不产生 `ContentChange`；
    - 模型输出未携带 YAML frontmatter（`---`）或输出格式异常时抛出验证错误；
    - 模型输出与基线内容无实质变更（`candidateHash === baseHash` 或内容完全一致）时抛出 422 拒绝；
    - 坏输出绝不成为可批准候选，正本 hash 始终不变。
  - **落盘候选与记录变更**：成功输出通过 C07 `CandidateFileRepository.save` 写入独立候选仓储，并通过 C02 `ContentChangeRepository.createOnce` 创建状态为 `PROPOSED` 的不可变变更记录，关联 `sourceRunId`。
- **管理端 HTTP 控制器**：
  - 新增 `apps/api/src/content-mutation/content-change.controller.ts`，注册于 `KernelModule`，受全局 `AdminTokenMiddleware` 保护。
  - 提供 `POST /ops/content-changes`（发起候选生成）、`GET /ops/content-changes`（候选列表筛选）与 `GET /ops/content-changes/:id`（候选详情）。
