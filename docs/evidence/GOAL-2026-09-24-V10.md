- **理由**：`to-do.md` 记录 R01–R33 与 V01–V09 已完成；V10 的前置均已满足。现有部署解析、已核验公开快照、只读工具配置和统一执行队列均可复用。

旧 `/assistant` 与 `/assistant/stream` 请求经服务端解析位置、已启用部署、固定修订和已核验公开快照后，进入同一公共只读执行生命周期。没有有效部署、快照、额度或可用模型时返回明确的规则回答；公开来源不能获得写动作或管理权限。

## 目标定义

- **类型**：技术 / 产品行为。
- **边界**：仅完成 `to-do.md` 的 V10；接入现有两个公开端点、部署解析、公开快照、脱敏、统一队列/额度与规则降级。
- **非目标**：V11 的 SSE v2 与交付确认；V12 的文章页 UI；V13 的多 Agent 切换与历史恢复；V14 的访客停止 API；生产启用和部署。
- **验证规则**：公共 AI 调用只可能由统一执行服务在已启用、已核验的只读修订上启动。
- **证据来源**：API 单元/Kernel 集成行为、类型检查、API 构建、API 契约文档。
- **通过标准**：AI 关闭、无已部署位置、无快照、队列/额度拒绝或执行超时均返回规则回答并保留真实降级原因；成功请求的 `origin=public`、`kind=chat`、资源范围绑定当前文章；伪造写动作/授权字段被拒绝。
- **置信度说明**：隔离 SQLite Kernel 集成可证明服务端接线、策略和持久生命周期；模型行为沿用已通过 R21 的 SDK 探针，V10 不以 mock 代替真实 R21 证据。
- **判定主体**：仓库验收条件决定本地完成；站主决定是否允许后续公开启用，G08 才核生产状态。

## 当前状态

- `DeploymentService.resolve` 只返回启用且当前三类测试合格的默认修订。
- `FsSiteContentIndex` 只从已核验快照读取 `readable && citable` 内容，并按 deny 集合即时收窄。
- `AgentExecutionService` 已有公共队列、公平调度、统一运行状态和权限交集；两个公开 POST 路由现由 `PublicAssistantService` 调用专用 `runPublicChat` 入口。
- 旧请求 DTO 没有位置字段；缺少位置时必须保持规则回答，不能推断或自动启用部署。V12 再把文章页上下文接入。
- 工作树已有用户未提交改动，实施时保留全部既有状态，不做 reset/clean/stash。

## Dry-run 发现

- 现有 `/assistant` DTO 不携带文章 slug，因此旧客户端不能安全绑定文章；路线明确为无位置时走规则回答，V12 再补页面上下文。
- 统一执行服务已有公共 lane，但没有公开专用结果等待/读取方法；需在服务端受控地等待本请求结果，不能开放管理运行记录查询路由。
- `PrismaExecutionQuota` 对无 grant 的公共任务不扣授权额度；每日助手预算与公共队列上限必须保留，不能给 public 伪造后台 grant。
- 数据库已包含 `deploymentGeneration` / `contentSnapshotId`；V10 只增补 `deploymentId` / `placementKey` 和 SDK session 的 `agentRevisionId`，不复制快照正文或凭据。
