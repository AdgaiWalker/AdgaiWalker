# O08：实现一次内容更新复盘

前置：O01、C24、O06。落点：ReviewEntry service/controller、admin records 复盘表单。
验收：K2/K3；保存可回看、指标有来源，样本不足可明确写未知；模型建议不能自动变成已验证成效。

## 1. 实现

### 1.1 契约与领域模型扩展

- shared 新增只读合同 `ReviewEntryView`（`packages/shared/src/reminder.ts`），前端与 API 统一类型定义；
- 字段语义清晰且严格：
  - `didWhat`：客观做了什么变更（必填）；
  - `observed`：观察到的客观结果（选填，自由文本）；
  - `windowStart`, `windowEnd`：观察窗口（选填）；
  - `evidenceState`：证据充分度（`UNKNOWN` | `INSUFFICIENT` | `SUFFICIENT`，默认 `UNKNOWN`，**样本不足如实写未知**）；
  - `evidenceNote`：指标与证据来源说明（记录统计窗口、样本量、数据来源，例如引用 `/ops/overview`）；
  - `nextAttempt`：下一次尝试（自由文本建议，供 O09 显式转化）；
  - `actionId`：关联事项；
  - `releaseId`：关联已核验发布版本（若提供，其阶段必须为 `PUBLISHED`）；
  - `createdBy`：操作人（固定为人工站主，模型无法自主创建复盘）。

### 1.2 服务端与接口实现（`ReminderService` / `ReminderController`）

- `createReview` 完善发布版本关联校验：若传入 `releaseId` 且存在发布记录，校验其 stage 必须为 `PUBLISHED`（否则抛出 400 `review-release-must-be-published`，杜绝关联未上线或失败的发布草稿）；
- `listReviews`：无 `actionId` 传参时查询全局复盘列表（支持运营记录展示），传 `actionId` 时支持特定事项过滤；
- 幂等性：基于 `requestKey` 数据库唯一索引，重复提交直接返回既有记录，不产生第二次副作用；
- 安全红线：**模型建议不能自动变成已验证成效**——只有人工站主在工作台显式提交才落库，不自动选题、不自动修改内容或自动发布。

### 1.3 前端更新复盘面板（`ContentReviewPanel.tsx`）

- 在 `RunListPage.tsx` 增加「更新复盘」标签页（`tab=reviews`），挂载 `ContentReviewPanel`；
- 表单支持录入事项 ID、发布版本 ID、行为说明、观察结果、窗口、证据充分度、指标来源说明、下一次尝试；
- 历史卡片列表呈现完整复盘事实，证据状态清晰标示徽章：
  - `UNKNOWN`：证据未知 / 样本不足（灰底徽章）；
  - `INSUFFICIENT`：证据尚不充分（橙底徽章）；
  - `SUFFICIENT`：已验证成效（绿底徽章）；
- 展现指标来源说明，以及突出的下一次尝试文本块；
- 无复盘时提供友好空态指引。
