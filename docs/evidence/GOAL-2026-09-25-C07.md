# C07：实现独立候选文件仓储

## 实施结果

- **候选文件端口与记录结构**：在 `apps/api/src/ports/candidate-file.repository.ts` 定义了 `CandidateFileRepositoryPort`（`save`、`read`）与 `CandidateFileRecord`，按 `candidateId` / `hash` 保存不可变结果，解耦作品流水线（不强制先建 8 阶段 work 流水线）。
- **受控文件适配器**：在 `apps/api/src/adapters/fs-candidate-file.repository.ts` 实现了 `FsCandidateFileRepository`：
  - 路径由服务端在受控候选目录（可由 `WALKER_CANDIDATES_DIR` 配置）下统一计算生成，临时文件写入并以 `fs.rename` 原子替换。
  - 生成满足 `isContentOpaqueId` 的 opaque 引用格式 `${candidateId}_${hash}`。
  - **幂等复用与不可变保护**：相同 `candidateId` 与相同 `hash` 重复保存可幂等复用；相同 `candidateId` 试图写入不同 `hash` 时抛出 409（`candidate-conflict`）拒绝篡改。
  - **读取严格核验 hash**：`read(candidateRef)` 提取引用中的 expectedHash，并校验文件内容实测 SHA-256；若文件被篡改或损坏，抛出 `candidate-hash-mismatch`。
  - **安全防范**：严格校验 `candidateId` 与 `candidateRef` 不透明标识符，禁止 `..`、绝对路径与路径分隔符，物理限定在受控根目录内，绝对无法读取或覆盖 `content/log`。
- **Kernel 接线与消费**：在 `KernelModule` 注册 `CANDIDATE_FILE_REPOSITORY`；并在 `ContentMutationService` 中打通了通过 `candidateRef` 自动从候选仓储读取正文并核验应用的能力。
