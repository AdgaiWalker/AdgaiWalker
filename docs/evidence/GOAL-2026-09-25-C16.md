# C16：实现线上版本核验器

## 实施结果

- **核验契约升级（`WebsiteDeploymentVerifierPort`）**：
  - 输入从 `{ title }` 扩展为 `VerifyWebsiteDeploymentInput`：`title?`、`expectedHash?`、`slug?`、`manifestUrl?`、`timeoutMs?`、`retries?`、`retryDelayMs?`；旧字段保持可选，既有工作站调用无需改动。
  - 返回 `VerifyWebsiteDeploymentResult`：`ok`、`verifiedHash`、`observedTitle`、`htmlMatched`、`manifestMatched`、`reason`。
- **线上核验适配器（`HttpWebsiteDeploymentVerifier`）**：
  - **不再只匹配标题或页面 200**：从文章 HTML 提取 `<meta name="content-hash">` 或 `data-content-hash`，与期望 hash 严格比对，不符即判未确证（含 `html-hash-mismatch` 原因）。
  - 同时核验线上 `public-manifest.json` 中该 slug 的条目 hash，作为第二重版本证据。
  - **缓存旧响应处理**：请求统一附加禁缓存头（`no-cache, no-store, must-revalidate` + `pragma: no-cache`）与破缓存参数 `_t=<ts>`，避免读到 CDN/代理旧版本。
  - **超时与重试边界**：单次核验受 `timeoutMs` 约束（`AbortController`），超时如实标注 `verification-timeout`；按 `retries`/`retryDelayMs` 复检，用于 Vercel 尚未生效的窗口。
  - 未指定 `expectedHash` 时退回标题校验，保持旧工作站语义。
- **阶段推进门禁（`ContentReleaseService.verify`）**：
  - 暴露 `POST /admin/content/release/:id/verify`。
  - 仅当线上**确证目标 hash**（`ok === true` 且 `verifiedHash === release.sourceHash`）才把 `VERIFYING` 推进为 `PUBLISHED`，并写入 `verifiedHash`/`verifiedAt`。
  - 旧网页、同标题旧正文、失败部署、缺少 hash 证据一律保持 `VERIFYING`，返回 `verified: false` 与原因，绝不提前记为已发布。
  - 重复核验幂等：已 `PUBLISHED` 直接返回，不再请求线上。
  - 非 `VERIFYING` 状态调用核验抛 409 `content-release-not-verifying`。
  - 仓库层 `updateStage` 的状态机同样强制 `expectedHash === verifiedHash` 才能进入 `PUBLISHED`（双重保险）。
