# V20 会话日志查询与后台回看

## 目标与边界

交付 `ops/conversations` 管理只读查询和 Records 页访客会话回看：按内容、位置、Agent、日期、运行状态、关键词过滤；使用 50/100 条稳定游标；详情串起问题、回答、引用、版本、执行和助手交互事件。已删或超过当前明细保留期的会话不能从列表/详情读出。

访客 Agent 没有此端点或全局历史查询工具；API 路由走默认管理凭据门禁，不加入公开白名单。V20 不提供编辑、删除或导出操作。

## 实现

- `GET /ops/conversations` 由 `ConversationQueryService` 校验 limit、日期、状态和 opaque cursor；`PrismaConversationQueryRepository` 在 SQLite 内执行关联过滤，不先把所有会话加载进 Node。列表按最近提问活动倒序，游标绑定 `(updatedAt,id)`；新增 `Conversation(updatedAt,id)` 索引。
- 关键词在服务端匹配会话全部 visitor/assistant message 正文；列表只返回最近问题摘要和活动元数据，不包含最近回答全文。详情 `GET /ops/conversations/:conversationId` 按轮返回消息、送达状态、引用、Agent 修订、公开 Run/Event、组件交互/反馈。匿名 ID、SDK Session ID 和物理路径不返回。
- 列表和详情同时排除任意状态的 `DeletionTombstone` 会话，并按当前 `LogRetentionPolicy.detailRetentionDays` 计算 cutoff；缩短保留期后，后台查询立即隐藏超期会话，启动清理稍后回收物理资源。
- Run 的 `tokensIn/tokensOut` 保持 `number | null`；服务端不从旧 AssistantRun 默认 0 推断实际用量。前端显示 `null` 为“未知”，实际 0 显示“0”。
- `GET /ops/capabilities` 通过 query repository health probe 动态显示 `conversations=available/unavailable`。
- Admin Records 增加访客对话筛选列表和详情页。查询通过现有 requestJson/React Query；筛选写入 URL，能刷新和回退。桌面/移动端用横向滚动语义表格，详情显示逐轮输入/对外回答、引用、降级原因、运行用量/事件和交互反馈。只使用 Lucide 图标。

## K3：Records 页面浏览器流程

目标流程：`/records` → 选择“访客对话” → 按关键词、文章、位置与“无运行记录”筛选 → 打开会话详情 → 回看消息、引用与交互事件。

- 使用隔离 `apps/api/data/v20-browser.test.db`，API `AI_ENABLED=false`；通过本地公开问答生成一条专用测试会话，没有调用真实模型或生产数据。
- Ego browser 验证桌面 1200×772 与移动 390×844。页面身份与标题正确，没有空白壳或 React/Vite 错误覆盖；筛选后的 URL 带入所有条件，结果仅返回目标会话，详情展示问题、规则回答、三条引用、送达状态与交互记录。
- 浏览器截图：桌面筛选列表和 390px 移动列表均已实际查看，移动表格保持横向滚动；截图保存在本轮临时 QA 目录，不纳入仓库。详情页面的正文、引用和投递状态通过浏览器 snapshot 检查，attempt/success 交互标签的中文展示由组件测试确认。
- Browser plugin 未列于此会话，Playwright 包/命令也未安装；使用已安装的 Ego browser 完成 DOM、交互和截图验证。初次页面导航有一次 `/favicon.ico` 404（与 V20 页面逻辑无关）；目标流程无 JavaScript 异常。
