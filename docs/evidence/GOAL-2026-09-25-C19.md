# C19：实现发布脚本的进程树终止核验

## 实施结果

- **受控进程树工具（`apps/api/src/common/process-tree.ts`）**：
  - `isPidAlive`：精准检测 PID 存活状态；
  - `getProcessDescendants`：递归查询进程树中的所有子进程 PID，不遗漏构建与 Git 派生的任何后代进程；
  - `terminateAndVerifyProcessTree`：跨平台终止整棵进程树（POSIX 进程组 / Windows `taskkill /PID <pid> /T /F`，超时升级 `SIGKILL`），并**轮询核验确认整棵树上的全部子进程均已退出**，杜绝孤儿僵尸进程占满 2C2G 资源，不误杀其他程序。
- **发布进程适配器升级（`PnpmContentReleaseRunner`）**：
  - 支持 `RunReleaseOptions`（`signal`、`onSpawn`），记录脚本树归属（根 PID 登记）；
  - 超时与取消时调用 `terminateAndVerifyProcessTree` 终止整棵进程树；
  - 保持形参为 0（无命令字符串可注入）。
- **取消与请求停止核对逻辑（`ContentReleaseService.cancel`）**：
  - **构建阶段安全终止**：若 release 处于 `PREPARED` 或 `COMMITTING`，向 runner 发送取消信号并终止进程树，确证子进程退出后将阶段置为 `FAILED`（`errorCode: 'cancelled-before-commit'`），未产生提交、未推送任何内容；
  - **核心红线：已推送（PUSHED / VERIFYING）绝不假装取消**：
    - 若已经推进到 `PUSHED` 或 `VERIFYING`，push 已经派发；
    - 绝不能将可能已上线的操作标为“取消且未发布（FAILED）”；
    - 中止本地监听后立即调用 C18 的 `reconcile` 核对实际效果：若线上已确证目标版本，置为 `PUBLISHED`；若线上未生效，保持 `VERIFYING` 并等待部署核验。
- **控制器端点暴露**：
  - 在 `ContentReleaseController` 暴露 `POST /admin/content/release/:id/cancel`。
