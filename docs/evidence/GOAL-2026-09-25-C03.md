# C03：内容文件对象锁与 CAS 保存

## 实施结果

- `ContentFileDetail` 增加 `hash`，按当前正文 UTF-8 字节计算 SHA-256。
- `ContentFileRepositoryPort.save(slug, raw, expectedHash)` 要求显式版本条件：存在文件必须匹配当前 hash；`null` 只允许创建不存在的目标。不存在/已存在与调用预期不一致时返回 `content-version-conflict`。
- `FsContentFileRepository` 在同一 API 进程内按绝对内容目录和 slug 排队。锁覆盖扩展名解析、目标读取/hash 比较、完整临时文件写入和替换；同时存在 `.md` 与 `.mdx` 或目标不是普通文件时拒绝写入。
- 写入使用目标目录中的唯一临时文件，`wx` 排他打开，沿用旧文件权限或新文件 `0644`，写完整正文后 `sync()`、关闭句柄并 `rename()` 替换。写入/替换失败关闭句柄并删临时文件，旧正文不受影响。
- slug 继续使用小写 ASCII 短横线规则，路径穿越、大小写变体和其他格式在打开路径前拒绝。
- `GET /admin/content/:slug` 返回 `hash`；`PUT /admin/content/:slug` 必须显式带 `{ raw, expectedHash }`，缺失版本条件拒绝。旧工作站生成文章时先读取当前 hash 再写入；不会把两参数旧签名留作兼容分支。
- 现有保存后 `content:gen` 仍由 `ContentAdminService` 触发；C05 会将它移出受控保存动作。C03 没有加持久写入意图/审计或跨进程协调。

## Hai TDD

### Target Behavior

对同一内容 slug 的写操作串行化，并让保存仅在调用方所见版本仍是当前版本时成功。先把完整内容写入同目录临时文件并同步，再替换正本；临时写入或替换失败时，正本保持完整。拒绝路径穿越和不支持的 slug。

- **Test added**: `apps/api/src/adapters/fs-content-file.repository.test.ts` 的并发 CAS、错误 expectedHash、临时替换故障用例；`apps/api/src/content-admin/content-admin.controller.test.ts` 的版本条件请求用例。
- **Behavior asserted**: 两个 repository 实例基于同一旧 hash 并发保存只能成功一次；hash 过期不得覆盖；原子替换未实现时故障不能谎报成功；API 保存必须带 `expectedHash`。

## 验收边界

- 内容文件锁是单进程内锁。它不协调其他 API 进程或仓库外的直接文件/Git 修改；部署当前使用单 API 实例。跨重启意图、部分副作用恢复由 C04 完成，发布全工作区锁由后续任务完成。
- 本次只用临时目录和隔离测试库验证，没有修改 `content/log` 正本，没有进行 Windows 或生产文件系统验证，也未部署。
- 旧 `/admin/content` 保存仍由现有服务触发 `content:gen`，目前仍是管理端已鉴权写路径；C05 会将保存审计、受控副作用和索引刷新边界收口。
