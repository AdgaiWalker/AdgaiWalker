## 1. 目标与实现内容

依据 PRD A8/A9、TECH-DESIGN §6.2 与原子清单 C20 要求，实现并接通发布清单和版本状态管理界面：

1. **三版本状态对比与同步差异展示**：
   - 工作区编辑正本版本（`workingHash`）
   - 网页发布版本（`publishedHash`，线上确证事实）
   - 问答快照版本（`indexedHash`，公开助理快照索引）
   - 实时对比并显示同步状态徽章（如“与工作区一致”、“有待发布修改”、“索引待同步”等）。

2. **5秒可见轮询与 15秒标陈旧机制**：
   - 页面可见性感知：当浏览器标签页处于活跃可见状态（`document.visibilityState === 'visible'`）时，以 5 秒（`5,000ms`）周期轮询后端最新事实状态；标签页休眠或切后台时暂停轮询。
   - 陈旧状态标记：精确记录最近一次成功接收事实数据的时间戳 `lastFetchedAt`，当超过 15 秒（`15,000ms`）未获取到新状态时，显式展示琥珀色告警徽章并提示数据已陈旧，同时提供“立即刷新”按钮手动重试。

3. **实际发布范围与阻塞路径展示**：
   - 调用预检接口 `POST /admin/content/release/preflight`：
     - 若预检阻塞（`ok: false`）：展示阻塞原因（`scopeConflict.reason` 如 `code-dirty`, `support-config-dirty`, `other-content-dirty`）、阻塞说明与冲突文件路径列表（`scopeConflict.details`）；缺失必需字段时展示缺失字段清单，并禁用发布按钮。
     - 若预检通过（`ok: true`）：展示结构化稳定清单 `manifest`（包含 `targetSlug`, `targetHash`, `headCommit`, `manifestHash`, `createdAt`），以及将要提交的文件列表表格（`path`, `kind`, `status`, `hash`）。

4. **独立发布批准与防重复点击保护**：
   - 严格区分候选应用（`apply-candidate`）与网页发布（`publish-website`）两类副作用，提供独立的发布审批输入与执行动作。
   - 绑定 L2 授权（`grantId`）并构造不可变 `publishApproval`，调用后端 `POST /admin/content/release/prepare` 登记 PREPARED 阶段的发布单事实。
   - 执行发布上线时，在请求派发与进行中阶段全面禁用按钮并展示正在发布中状态，有效杜绝重复点击与二次并发派发。

5. **发布阶段状态机与失败解释（诚实原则）**：
   - 跟踪并展示发布阶段全流程：`PREPARED` → `COMMITTING` → `PUSHED` → `VERIFYING` → `PUBLISHED` / `FAILED` / `UNKNOWN`。
   - 独立呈现问答快照同步状态（`assistantIndexState`：`PENDING` / `SYNCING` / `SYNCED` / `FAILED` / `UNKNOWN`）。
   - 失败处理：对于 `FAILED` 或 `UNKNOWN` 阶段，展示明确的错误代码与原因解释，恪守诚实原则：“系统不会假定或承诺自动回滚已成功。线上内容状态可能保持旧版，也可能已部分生效，请通过核验与核对确认。”
   - 提供动作入口：核对真实状态（`reconcile`）、重试线上核验（`verify`）与受控取消（`cancel`）。
   - 刷新页面后完全依赖服务端持久模型（`GET /admin/content/release/target/:slug/latest` 与版本快照）无损恢复当前真实阶段。
