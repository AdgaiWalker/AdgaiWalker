# V18 可重试会话删除与防复活

## 目标与边界

完成 V17 资源登记之后的会话删除闭环：删除开始后立即禁止该会话新增或读取数据，停止关联公开执行，再清理数据库、原生 session、trace 和事件 spool 副本；进程中断或某一步失败时可继续清理。删除审计保留操作者、动作、目标和结果，不保留被删正文。

本地 API 与 SQLite 通过验收，生产未部署。此项没有增加管理 UI。按日期范围删除、删除前管理界面范围预览、备份恢复重放删除事实仍属于后续需求（备份恢复见 V19）。当前没有会话导出写入端；如果将来登记 export 资源，清理器会 fail-closed 并阻止任务完成，待导出能力接入时补上对应清理。

## 实现

- `ConversationDeletionService` 在 Operations Journal 事务中创建唯一 `DeletionTombstone` 并写入 `conversation-delete-requested` 审计，之后才停止运行或触碰正文。无法写入审计时不开始删除。
- 删除按资源登记逐步处理：native fork/session、trace、spool、FeatureEvent、消息、AssistantRun、ExecutionEvent/Run 及其附属状态；确认登记清空后，在单一数据库事务中删除剩余业务记录和 Conversation 并将墓碑置为 `completed`。
- 每个步骤可重入。失败保留墓碑并将任务设为 `blocked`，只暴露白名单错误码；重复调用同一会话 DELETE 会重试。服务启动及每 30 秒恢复 `pending`、`stopping`、`deleting`；`blocked` 需站主显式重试。
- 删除期间公开问答/历史/交互和会话创建被墓碑拒绝；正文写入和资源登记受事务内墓碑检查保护。spool 事件记录与回放会识别墓碑，不将其重新写进数据库。正在退出的运行通知仍可登记刚生成的原生 session/fork，使删除阶段能找到并清除。
- 文件清理仅依据资源逻辑 key、Agent 修订和应用自己的 Harness 目录推导路径；不接受客户端路径，清理前拒绝 root symlink、目标 symlink 和目录越界。Trace 和 spool 清理以缺失文件为成功，可安全重试。
- 管理 API：`DELETE /admin/log-resources/conversations/:conversationId`、`GET /admin/log-deletions/:id`。默认 AdminTokenMiddleware 鉴权；DELETE 经 SameOriginMiddleware。响应只有任务状态和安全错误码，不包含正文、resource key 或物理路径。

## 验收证据

| 验收点 | 证据 |
|---|---|
| 先建立墓碑/审计，运行停止证明前不清理正文 | `conversation-deletion.service.test.ts` 覆盖执行顺序、未确认停止时阻止清理、审计落库失败时拒绝启动 |
| 中断后可恢复，清理失败可重试 | service 测试先让文件清理失败，再重复 DELETE 完成；以已持久化 `deleting` 状态调用 `resumePending()` 模拟服务重启恢复 |
| spool 不复活已删除会话 | `assistant-event-recorder.service.test.ts` 覆盖 tombstone 事件不入 spool、队列回放发现墓碑后丢弃；kernel 集成确认删除时队列副本被清理 |
| 删除所有已登记正文副本，其他会话不受影响 | `conversation-deletion.kernel.integration.test.ts` 使用真实 AppModule 和隔离 SQLite，写入 visitor/assistant message、AssistantRun、公开 ExecutionRun/Event、FeatureEvent、native session 文件、trace 和 spool；删除后检查资源不存在，另一会话正文保留 |
| 审计不含删除正文，墓碑阻止重建 | 同一 HTTP/SQLite 集成检查审计没有访客/助手正文，且同 ID 的 Conversation 创建返回 `conversation-deleted` |
| 管理接口授权和任务查询 | 集成验证无 token 401、跨 Origin DELETE 403、带管理 token 的 DELETE 与状态 GET 成功 |
| 原生 session 路径安全 | `fs-log-resource.cleaner.test.ts` 覆盖目标 session 清理和 symlink 拒绝；`dsh-session-resource-path.test.ts` 锁定当前 pin 的上游目录编码规则 |

`resumePending()` 是用已有数据库状态验证启动恢复分支；本次没有实际杀进程、断电或从备份恢复。V19 会覆盖备份恢复窗口。
