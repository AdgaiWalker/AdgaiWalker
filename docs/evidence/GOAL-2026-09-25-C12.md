# C12：实现实际发布范围预检

## 实施结果

- **工作区 Git 状态接口与适配器（`GitStatusPort.workspaceSnapshot`）**：
  - 在 `apps/api/src/ports/git-status.repository.ts` 定义了 `GitFileStatus` 与 `WorkspaceGitStatus`。
  - 在 `apps/api/src/adapters/node-git-status.repository.ts` 实现了单次 `git status --porcelain -z` 与 `git log -1 --format=%H` 的 O(1) 全仓状态解析，无 shell，Windows 安全，解析全部 dirty/staged 文件。
- **发布范围预检与 Manifest 稳定生成（`ContentReleaseService.preflight`）**：
  - **不仅仅检查 A 的 frontmatter**：在检验目标文章必需字段的同时，复核工作区真实 Git 状态与正本内容真实 hash。
  - **单篇发布范围冲突拦截（scope-conflict）**：
    - 若除当前文章 A 外，存在其他文章 B 未提交变更，返回 `scopeConflict.reason: 'other-content-dirty'`，触发发布时抛出 409（`scope-conflict`）拒绝发布；
    - 若 `content/support-config.json` 存在未提交修改，返回 `scopeConflict.reason: 'support-config-dirty'`；
    - **保留“不夹带代码”检查**：若工作区中 `apps/`、`packages/`、`scripts/` 或根配置等代码文件处于脏状态，返回 `scopeConflict.reason: 'code-dirty'`，坚决禁止代码与文章混杂夹带上线。
  - **生成稳定清单 Manifest**：
    - 预检通过后生成包含 `targetSlug`、`targetHash`（正本 SHA-256）、`headCommit`、条目列表与稳定 `manifestHash`（结构化 SHA-256）的不可变清单。
    - 连续调用哈希计算严格幂等稳定，清单可见。
- **发布动作保护（`ContentReleaseService.release`）**：
  - 触发发布时复调 `preflight`，遇范围冲突立即抛出 409（`scope-conflict`），绝不启动发布子进程，不触碰 Git 操作。
