# V23：公共位置启用前检查

## 目标与结论

公共位置只能在所有安全与运行门槛满足时启用。服务端在启用、启用中的回退和公开模型解析前重新核验 readiness；Admin 明确展示 blocker。任一 gate 缺失或检查失败都关闭启用/公开解析，客户端提供 `canEnable`、`force` 等布尔值不能绕过。

V23 已完成本地代码与自动化验收，未部署。当前 `apps/api/.env` 没有配置 `WALKER_RUNTIME_PROBE_REPORT`，readiness 按缺少运行证据保持 blocked；仓库中的最近脱敏探针记录也显示本机 dsh 目录没有可用模型通道。没有触发真实模型请求。

## 改动摘要

- shared 新增 readiness DTO 和六个 gate：核验快照、成员权限、运行隔离、日志保留、删除恢复、公开路由。
- `GET /ops/deployments/:id/readiness` 只走管理鉴权，返回逐 gate 的状态、原因、详情及派生的 `canEnable`。
- `POST /ops/deployments/:id/enable` 在写库前重新计算所有 gate；权限/测试失败返回 403，其他门槛失败返回 409 `public-readiness-blocked`。启用中的回退也检查全量 gate。
- 已启用部署在公开 manifest 和模型成员解析时检查 readiness；门槛失效后 manifest 返回不可用，模型解析返回 503。
- 删除恢复 gate 会核对 restore gate、删除清单读写能力与 replay 完成状态，以及未完成 tombstone。
- 公共路由 gate 将 Nest 唯一方法/路径排除清单与当前工作区 Caddyfile 对照。生产 Caddy 实际加载状态仍由 G08 核验。
- Admin 部署列表逐项呈现 blocker；请求仍在加载、失败或缺报告时启用按钮保持禁用，使用 Lucide 图标。
- 加强运行探针判定，只有 status、非空回答、64 位 SHA-256、`closeError=null`、`processExited=true` 都齐全才算通过。探针脚本不再强制注入 `WALKER_DSH_RUNTIME_BIN`；退出使用 `process.exitCode`，以便 `finally` 清理临时会话目录，并且不把本地模型目录绝对路径写入脱敏报告。
