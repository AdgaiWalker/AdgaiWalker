# V22：公共路由白名单与安全边界

## 目标与边界

Nest 的公开豁免与 Caddy 公网转发必须按 HTTP 方法和路径完全一致；`/ops`、导出、删除、内容写入和其他管理面保持私有。浏览器写请求验证 Origin/Referer；同源 Vite 代理不能改写浏览器 Host；不开放宽泛 CORS。

本地完成代码/测试与公开路径对照，未运行生产 Caddy、未更改服务器 `.env`、未部署。生产部署前需确认 `WALKER_PUBLIC_ORIGINS` 包含真实公开站点 host `www.iwalk.pro`。

## 改动摘要

- Nest `AdminTokenMiddleware.exclude` 和 Caddy 公网 matcher 固定为 13 个 HTTP 方法/路径组合。移除 `GET /support` 的公网豁免与 Caddy 转发：当前 Web `/support` 页使用构建期 `content/support-config.json`，没有 API 调用；Nest 保留的 `/support` 由管理凭据保护。
- 新 `apps/api/src/public-route-boundary.test.ts` 从实际 `AppModule.configure()` 捕获公开豁免，解析 `Caddyfile` 的公网 matcher，并逐项核验允许集合、HTTP 方法、私有管理面与默认 404。允许清单：

| 方法 | 路径 |
|---|---|
| GET | `/health`、`/assistant/placements/*/*`、`/assistant/conversations/*/*`、`/likes` |
| POST | `/intake`、`/assistant`、`/assistant/stream`、`/assistant/events`、`/assistant/conversations/*/*/stop`、`/assistant/messages/*/ack`、`/likes`、`/content-feedback`、`/search-events` |

- `SameOriginMiddleware` 改为全局接收所有变更方法并仅拦截 POST/PUT/PATCH/DELETE：Origin/Referer host 必须等于请求 Host 或精确命中 `WALKER_PUBLIC_ORIGINS`；脚本没有 Origin/Referer 时可继续，浏览器跨站变更返回 403。`WALKER_PUBLIC_ORIGINS` 使用逗号分隔的 host，不带 scheme。
- Nest 不启用全局 CORS。恶意源预检没有 `Access-Control-Allow-Origin`。Caddy 只转发显式 matcher，未命中返回 404。
- Web/Admin 两个 Vite `/api` 代理都改为 `changeOrigin:false`，保持请求 Host 与浏览器 Origin 一致。各自的 `vite-proxy.test.ts` 通过 `loadConfigFromFile` 读取实际 Vite 配置。
- `WALKER_PUBLIC_ORIGINS=www.iwalk.pro` 已写入生产 `.env` 示例与运维说明；此修改只落文档，没有改服务器运行配置。

## 验收边界

- Caddy CLI 不在本机安装；本地以解析当前 `Caddyfile` 并与 Nest 运行配置逐项对照验证，没有执行 `caddy validate`，也没有发公网探针。
- `WALKER_PUBLIC_ORIGINS=www.iwalk.pro` 是部署要求，不代表服务器当前值已修改或生产配置已验证。
- 公开 `GET /health`、访客问答/会话、反馈/搜索等既有产品路由保留；公开白名单没有 `/admin`、`/ops`、`/support` 或内容写接口。
