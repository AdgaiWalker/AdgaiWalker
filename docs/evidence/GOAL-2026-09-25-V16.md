进度唯一来源：根 [`to-do.md`](../../to-do.md)

## 目标行为

助手运行指标和文章助手部件交互事件在 SQLite 短暂不可写时进入受控 spool，并以稳定 `eventId` 回放。重复入库不增加计数；队列过期、超限或本地存储不可用时，管理侧明确显示未知丢失量。回答生成后，次要历史持久化的失败或挂起不能把答案卡住。授权、审批和其他关键副作用审计继续失败关闭。

## 实现边界

- 文件队列放在绝对 SQLite `DATABASE_URL` 所在目录下的 `assistant-event-spool/`，不放进文章、Agent workspace 或生成工作目录。
- 每条事件独立写入临时文件后原子重命名；默认总量上限 20MiB、TTL 24 小时、权限 `0700/0600`。spool 缓存当前进程索引，避免每次入队都重新扫描目录。
- spool 仅包含 FeatureEvent 白名单元数据，不包含访客问题、助手回答、IP 或匿名明文。
- 数据库写入预算 250ms，超时、失败或重复都按同一稳定 ID 处理。进程启动时和每 30 秒最多回放 100 条；DB 返回 `duplicate` 也会删除 spool 项。
- `/admin/assistant-events/health` 受管理令牌保护，返回 `healthy`、`backlog` 或 `loss-unknown`，并提供待回放条数/字节数、最早入队时间及丢失计数；无法精确计数时 `droppedCount: null`。
- 回答生成后的 Conversation、session、run 和 token 保存最多等待 250ms；失败或挂起不改变已生成回答。已校验引用/成员/消息等依赖数据库的边界仍失败关闭。
- 未修改关键操作的 Operations Journal；审计失败仍回滚相关事务。

## RED

- **测试**：`fs-assistant-event-spool.test.ts`、`assistant-event-recorder.service.test.ts`、`PublicAssistantService` 保存挂起用例。
- **行为约束**：文件队列需要受限落盘、稳定 ID 去重、回放/删除、过期清理和未知丢失状态；保存挂起不能阻止答案返回。
- **观察结果**：最初分别因 `fs-assistant-event-spool` 与 `assistant-event-recorder.service` 模块缺失而无法加载。回答保存挂起测试在 350ms 截止处得到 `timed-out`。
- **失败正确性**：导入目标实现路径不存在，且保存挂起用例确实停在 final persistence；不是环境或断言语法错误。
- **授权边界修正**：全量 API 回归首次发现原始数据库错误被当作无部署后返回规则答案，导致部署代次冲突可能被吞掉。现在 `ApiError` 原样抛出；只有非业务存储故障回退规则回答。
