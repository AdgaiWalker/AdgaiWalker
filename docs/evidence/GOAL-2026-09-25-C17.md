# C17：接通发布后问答快照切换

## 实施结果

- **持久模型与仓储契约扩展**：
  - `ContentReleaseRepositoryPort` 增加 `updateIndexState(input)` 并在 `updateStage` 接受 `assistantIndexState?: ContentIndexSyncState` 与 `publishedSnapshotId?: string | null`。
  - `PrismaContentReleaseRepository` 实现独立快照索引同步状态流转（`PENDING` -> `SYNCING` -> `SYNCED` / `FAILED`），将网页发布结果与问答索引同步结果物理分离。
- **依赖注入与架构接线**：
  - 在 `KernelModule` 绑定 `{ provide: PUBLIC_SNAPSHOT_REPOSITORY, useClass: FsPublicSnapshotRepository }`。
  - `FsSiteContentIndex` 现支持可选注入 `PUBLIC_SNAPSHOT_REPOSITORY`，使问答只读基线与快照仓储在测试与运行环境中严格对齐。
- **发布核验后的自动快照切换与隔离防护**：
  - 在 `ContentReleaseService.verify` 中，当网页阶段经线上目标 hash 确证推进为 `PUBLISHED` 后，自动向已部署站点抓取 `public-manifest.json`。
  - **防止草稿外溢**：必须经由 `verifyPublicSnapshot` 校验线上清单自洽性，并核对清单中包含当前发布的 slug 且 hash 严格等于 `sourceHash`。绝不复制本地工作区草稿充当快照。
  - **状态与容灾独立（诚实原则）**：
    - 若快照同步成功，推进 `assistantIndexState: 'SYNCED'`，记录 `publishedSnapshotId: manifest.collectionHash`；
    - 若快照拉取异常、网络中断或 hash 不匹配，记录 `assistantIndexState: 'FAILED'`，返回 `reason: 'assistant-index-sync-failed'`。**网页阶段保持 `PUBLISHED`（承认已上线事实），同时旧快照完全不受破坏、继续对外可用**，杜绝“全量成功”假象。
- **版本快照独立推导**：
  - 在 `ContentReleaseService` 实现 `getVersionSnapshot(slug)`，并在 `ContentReleaseController` 暴露 `GET /admin/content/release/:slug/version`。
  - 分别从本地正本（`workingHash`）、已发布记录（`publishedHash`）与已激活问答快照（`indexedHash`）推导，三者在网页已上线但问答未同步时如实呈现不同真相。
