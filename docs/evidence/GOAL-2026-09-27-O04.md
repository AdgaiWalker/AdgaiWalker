# O04：接通事项与提醒箱界面

前置：O03、F14。落点：admin 概览下一动作、内容详情提醒入口。
验收：K3；创建后到期可见，刷新/重复点击状态稳定；提醒系统在 AI 关闭时仍工作。

## 1. 实现

### 1.1 服务端算到期，前端只展示（不把「今天/逾期」算法抄到浏览器）

- shared 新增提醒箱读模型（`packages/shared/src/reminder.ts`）：`REMINDER_DUE_STATES`、`ReminderInboxItem`、`ReminderInbox`、`classifyReminderDue`、`countReminderItems`。
- 新增 `GET /ops/reminders/inbox`（`ReminderService.inbox`）：只取 `status=OPEN` 事项，逐条带出到期状态与最近一次发生记录结果。
  - **分类用站点本地日期**：若用 UTC 日期，站点 00:00–08:00 期间的「今天到期」会被错判成「已到期」。
  - **计数不计已忽略项**：忽略的到期不抬高待办数。
- `ReminderInboxPanel` 内嵌到**概览页**与**内容详情「提醒」标签**：**不新增第五个主工作面**（验收要求）。

### 1.2 内容详情提醒入口

`ContentReminderPanel`：为某篇文章设置某日提醒（复用既有 Action，`entityType=CONTENT`、`entityId=slug`），默认提前 3 天；创建后下方提醒箱立即拉取，新提醒即刻可见。重复规则未实现，界面不提供周期开关（与 O03 的 501 一致）。

### 1.3 重复点击稳定（前端配合服务端幂等）

每个「处置按钮」自带**稳定 requestKey**：同一按钮重复点击复用同一键，服务端据此回放首次结果（`replayed: true`），界面如实提示「此前已生效（重复点击未产生第二次副作用）」，**不谎称又执行了一次**。换动作或换事项才换键——避免把不同操作当成同一次重试。

延后按钮按**本地日期 +7 天**计算，不用 UTC 运算（否则东八区会少算一天）。

## 2. 验证

### 2.1 前端组件测试（`ReminderInboxPanel.test.tsx`，9 项）

四类到期徽章与计数、站点时区/今天、UTC 瞬时展示；内容详情内嵌时只显示该内容的提醒；**同一按钮重复点击复用同一 requestKey**；幂等回放如实提示；延后 +7 天算出 `2026-09-27`（本地日期，不被 UTC 偏移带偏）；忽略带原因；失败如实报错；空态说明如何开始；读取失败显示 `ErrorState` 并给重试且**不显示任何假数据**。

### 2.2 shared 纯函数测试（13 项，含新增 3 项）

分类四态；**跨日边界**：站点 `2026-09-26 00:00` 对应 UTC `2026-09-25T16:00Z`——若误用 UTC 日期当天到期会被错判为已到期，此处断言必须用本地日期；计数忽略已忽略项。

### 2.3 API 集成测试

`reminder-disposition-http.integration.test.ts` 新增一项：**AI 关闭时提醒系统仍完整工作**（该套件 `AI_ENABLED=false`）——创建带排期事项立即得到 `dueAt`；`GET /ops/reminders/inbox` 返回 `timezone=Asia/Shanghai`、该事项 `dueState='overdue'`；处置仍可执行。
