# C10：接通候选差异与审批 UI

## 实施结果

- **候选审阅面板组件**：在 `apps/admin/src/pages/content/ContentChangeReviewPanel.tsx` 实现了针对单篇内容的候选审阅与审批面板，并接入 `ContentDetailPage.tsx` 选项卡体系。
- **差异可视化（能看清将修改什么）**：
  - 基于 C06 纯函数 `computeTextDiff`，比对正本当前内容与候选正文（`candidateRaw`），呈现新增行数（+）、删除行数（-）、未改动行数以及双列行号的行级彩色差异比对表。
- **动作、范围与关联信息呈现**：
  - 清晰呈现动作（`apply-candidate`）、目标范围（`content:${slug}`）、基线 hash、候选 hash 及来源 `sourceRunId`。
- **授权与失效原因诊断**：
  - 展示已绑定的审批人、审批时间与授权编号/修订。
  - 自动检测基线冲突：若正本在磁盘上已被修改导致当前 hash 不等于候选 `baseHash`，显式展示红色警示横幅说明失效原因：“正本在磁盘上已有新修改，与候选基线 hash 不匹配，原候选已失效”，并禁用批准与应用。
- **批准保存和批准发布分别操作**：
  - 提供“批准保存”按钮（调用受控 `POST /ops/content-changes/:id/approve`），可输入 L2 授权编号，重复点击幂等。
  - 提供“应用到工作区”按钮（调用受控 `POST /ops/content-changes/:id/apply`），重复点击幂等。
  - “批准发布”设立为独立按钮，与保存彻底解耦，明确标注“保存不等于发布；上线需通过发布预检与独立发布审批（C12/C13）”，严格落实 A02。
- **禁用持续自主内容授权入口**：
  - 审阅面板明确设置被禁用的“持续自主内容授权”入口，标注系统安全红线：“安全红线：后台已禁用持续自主内容授权入口，每次变更必须逐次人工审批。”
- **视觉规范**：全中文界面，全面使用 `lucide-react` 图标（`CheckCircle2`, `Save`, `AlertTriangle`, `Ban`, `ExternalLink`, `GitCompare`, `FileText`），零 Emoji。
