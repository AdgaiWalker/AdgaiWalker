# G02：完成完整失败恢复演练

前置：G01、C23、V19。落点：恢复脚本、可重放集成验收。
动作：合并验证进程孤儿、文件/DB 不一致、发布未知、补写与删除竞争、备份恢复；避免各模块恢复顺序互相打架。
验收：K6；恢复前不开放不可信状态，恢复后权限/正文/公开版本/删除事实一致；保留每个失败点结果。

## 1. 演练设计

新增 `recovery-order.g02.kernel.integration.test.ts`（6 项），在真实 KernelModule 接线下**逐点注入失败**并验证恢复行为，同时验证各模块恢复顺序不互相打架（与 `main.ts` 真实启动顺序一致：恢复门 → 清单重放 → 删除续跑）。

## 2. 五个失败点的验证结果（每个失败点保留结果）

| 失败点 | 注入方式 | 必须观察到的结果 | 结果 |
|---|---|---|---|
| **1. 恢复未完成** | 写入 `restore.pending` 闸门文件 | 闸门挂起期间一切请求 503 `restore-reconciliation-pending`，绝不放出半恢复数据；闸门路径推导恒定（同输入同落点），不存在第二套判定 | 通过 |
| **2. 进程孤儿** | `leaseOwner` 指向旧批次 + 进程观测为 `alive` | 租约不属于当前批次 → 标 UNKNOWN（不是伪造终态）；活着的孤儿绝不误判为已退出，槽继续占用防双开 | 通过 |
| **3. 发布结果未知** | 落一条 `stage='UNKNOWN'` 的发布记录（审批快照按真实规则构造） | UNKNOWN ≠ PUBLISHED；线上无证据时 reconcile 后仍不升级为 PUBLISHED、`verifiedHash` 保持 null；公开版本快照 `publishedHash` 为 null 不被污染 | 通过 |
| **4. 补写与删除竞争** | 删除完成后按真实时钟再写入一条资源登记（`registeredAt` 晚于 `completedAt`） | 墓碑保持 completed 终态不回退；迟到补写的资源被精确清除（删除事实优先） | 通过 |
| **5. 从旧备份恢复** | 删除完成后删掉墓碑、重建会话与正文（模拟备份早于删除） | 删除清单重放（force）把删除事实补回，复活的数据再次被清干净，恢复后删除事实一致 | 通过 |
| **顺序不打架** | 依次执行 清单重放 → 删除续跑 | 顺序与 main.ts 启动一致；删除续跑不重新打开已完成墓碑 | 通过 |

## 3. 发现并修复的真实缺陷：迟到补写永不清理

### 3.1 缺陷

`resumePending()` 只经 `pendingTombstones()` 查询 `pending/stopping/deleting` 三态——**已完成的墓碑永远不会被再次访问**。一旦删除完成后旧路径又写入资源登记（迟到补写），那条记录会**永久残留**，与「删除事实一致」的验收标准直接矛盾。

### 3.2 第一次修复的教训（过度清扫 → 并行测试互相打架）

第一版修复对"已完成且仍有资源"的墓碑做**全局清扫**（重跑 `finalizeConversation`）。合并验证立即暴露其危害：全量测试套件出现跨文件干扰（`conversation-export`、`content-review` 相继失败且失败集合在两次运行间漂移）——共享测试库中，某测试的清扫会伸手删掉并行测试的会话/运行数据。`finalizeConversation` 会连带删除 featureEvent、assistantRun、turns、conversation 及终止运行，作为"补写清扫"远超必要范围。

### 3.3 最终修复（精确判据）

改为 `lateWriteResources(limit)`：**只取 `resource.registeredAt > tombstone.completedAt` 的记录**——只认"删除完成之后才冒出来的写入"，不碰删除前已存在的任何数据。清扫动作限定为：文件 + 数据库正文 + 资源登记三步删除，**不重跑整段删除、不回退墓碑终态、不触碰会话行**。

修复后：G02 全部 6 项通过，log-resources 16 文件/34 项通过，**全量 api 139 文件/683 项全绿**——跨文件干扰消失，证明危害来自旧清扫的过宽范围而非测试基建。

### 3.4 接口变更

- `LogResourceRepositoryPort` 新增 `lateWriteResources(limit)`；
- `ConversationDeletionService.resumePending()` 在处理未完成墓碑后追加迟到补写清扫。
