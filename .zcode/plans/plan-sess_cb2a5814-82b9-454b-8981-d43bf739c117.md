# DeepSeek Harness 接入 Walker：阶段 0+1 实施计划

## 已定决策（沿用之前讨论结论）
- 执行框架：官方 deepseek-harness **0.1.2-alpha.1**（本地 clone `~/Desktop/deepseek-harness`，pnpm 工作流），不 vendor 进 Walker 仓库
- 模型：现成 DeepSeek key（`DEEPSEEK_API_KEY`，支持 `DEEPSEEK_BASE_URL` 换 OpenAI 兼容端点，架构不锁模型）
- 知识注入：整库进 prompt（复用已有的 `FsSiteContentIndex`，仅 citable 条目）
- Nest 唯一公开入口；Run 合同先行；规则兜底永远在；AI 可关

## 探索得出的关键技术选型
- 官方程序化形态是 **TS SDK client**（`@deepseek-ai/dsh-sdk-client`）**spawn `dsh --profile sdk` 子进程 + stdio JSON-RPC**，不是调 Web 实例的 HTTP（Web 层 loopback-only + 浏览器 cookie，明确不支持外部进程）
- V1 选 TS SDK client（高层 `DeepSeekHarness` API：`run()` / `session(id)` 多轮会话）。SDK 无 mid-turn cancel → 超时策略为「弃结果走兜底」；将来需要 cancel/close 再升 ACP profile（`--profile acp`，已确认含 `session/cancel`）
- 只读边界：环境变量 `DSH_PERMISSION_MODE=read-only`（沙箱只读 + ask 审批）；V1 助手不挂任何工具（整库已进 prompt，无需 bash/fs）

## 阶段 0：harness 本机跑通（不改 Walker 仓库，纯验证）
1. 环境核对：node（需 ^22.19.0 || >=24.0.0）、Corepack 启用 pnpm@11.7.0（仓库 packageManager 锁定值）
2. `cd ~/Desktop/deepseek-harness && pnpm install && pnpm run build`（源码跑必须先 build，缺 host artifacts 会启动失败）
3. 冒烟：`pnpm dsh headless "只回复 pong"`（headless 不监听端口、stdout 出答案，验证 runtime+模型链路）
4. 模型凭据：检查 `DEEPSEEK_API_KEY` 环境变量与 `~/.dsh/.credentials.yaml` 是否已有（iTab 时期可能配过；只检查存在性不读内容）；都没有则向用户要 key，以 env 方式注入，key 不进任何仓库
5. 实测 runtime 子进程常驻内存（腾讯云 2C2G 盒子部署的验收数据）；确认 `pnpm dsh --profile sdk` 可起
6. 产出：冒烟记录（命令/输出/内存数），作为「harness 可作服务运行时」的证据

## 阶段 1：Walker 侧接入（本仓库改动）
1. **Run 合同**：`AssistantRunContract` v1（版本化 JSON：question / answer / citations: slug[] / sessionId / turnId / aiUsedFlag / elapsedMs）——隔振 harness 后续破坏性变更
2. **新端口** `AssistantRunnerPort`（多轮）：`openSession(visitorKey)` / `ask(sessionId, text)`
3. **RuleAssistantAdapter 兜底**：AI 关闭时返回非空静态回答（热门文章推荐 + 卡口引导）
4. **DeepSeekHarnessAdapter**：SDK client + `dshBin` 指向本地 clone 的 runtime；`DSH_PERMISSION_MODE=read-only`；人设 + 整库 prompt（FsSiteContentIndex citable 集）作会话开场指令；`ask()` 包 15s 超时→弃结果走兜底
5. **/api/assistant 端点**：复用 anon-id / 限流 / guest-quota 基建；citations 必须 ⊆ citable 集合（fail-closed，同 nextStep 做法）；问题落 FeatureEvent（进线索池管线）
6. **单测**：AI 关兜底非空、超时兜底、非法 citation 拒收、AI_ENABLED 开关不调 runner
7. **本地端到端**：curl POST /api/assistant 问「duola 是谁」「想学 AI 从哪开始」，看回答质量与引用正确性

## 本轮不做
- web 对话框 UI、搜索无结果升级（下一轮）
- ACP 切换 / MCP / 多平台渠道
- 生产部署（盒子）与 Vercel 反代
- itab 相关一切

## 验收标准
- harness 冒烟通过，内存数据已记录
- AI 关：/api/assistant 返回非空静态回答（aiUsedFlag=false）
- AI 开：本地端到端正确回答「duola 是谁」并引用站内文章（citations ⊆ citable）
- 全仓 typecheck + 相关测试全绿
